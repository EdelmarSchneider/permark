--- h1 9-9
<h1 dir="auto" id="tidewell-open-data-api">Tidewell Open Data API</h1>
--- p 11-11
<p dir="auto">Every reading from every Tidewell buoy, free to use, in plain JSON. You don't need to sign up: a key only raises your rate limit.</p>
--- div 13-14
<div class="markdown-alert markdown-alert-note">
<p class="markdown-alert-title" dir="auto">Base URL</p>
<p dir="auto">Every endpoint lives under <a href="https://api.tidewell.example/v2">https://api.tidewell.example/v2</a>. Times are ISO 8601 in <abbr title="Coordinated Universal Time">UTC</abbr>, and values use the units of the <a href="station/buoy.toml">buoy settings</a>.</p>
</div>
--- pre 16-20
<pre><code class="language-bash" data-title="Quickstart"># The newest reading from Gannet Point. No key needed.
curl -s https://api.tidewell.example/v2/stations/LH-04/latest \
  -H "X-Tidewell-Client: my-first-script/1.0"
</code></pre>
--- h2 22-22
<h2 dir="auto" id="authentication">Authentication</h2>
--- p 24-24
<p dir="auto">Two headers matter. Both are plain text, and neither is required for your first request.</p>
--- dl 26-31
<dl>
<dt><code>Authorization</code></dt>
<dd>Optional. <code>Bearer &lt;your key&gt;</code>. A free key raises your limit from 60 to 600 requests a minute.</dd>
<dt><code>X-Tidewell-Client</code></dt>
<dd>Recommended. Your app's name and version, such as <code>harbor-dashboard/4.1</code>, so we can reach you before we have to slow down a runaway script.</dd>
</dl>
--- div 32-33
<div class="markdown-alert markdown-alert-warning">
<p class="markdown-alert-title" dir="auto">Keep keys out of your pages</p>
<p dir="auto">Never paste a key into a document, a notebook or a chat. Keep it in an environment file like <a href="station/deploy.env"><code>station/deploy.env</code></a>, and list that file in <a href=".aiignore"><code>.aiignore</code></a> so agents connected through PerMark never see it. Our own services read the base URL from <code>station/deploy.env:4</code>.</p>
</div>

--- h2 48-48
<h2 dir="auto" id="readings">Readings</h2>
--- p 50-50
<p dir="auto"><code>/v2/stations/{id}/readings</code> is the workhorse. It takes five query parameters:</p>
--- dl 52-63
<dl>
<dt><code>from</code>, <code>to</code></dt>
<dd>Start and end of the range. At most 31 days apart; <code>to</code> defaults to now.</dd>
<dt><code>fields</code></dt>
<dd>Comma-separated values to return, such as <code>temp_c,do_mgl</code>. Default: all five.</dd>
<dt><code>qc</code></dt>
<dd><code>published</code> (the default: passed and flagged readings) or <code>passed</code> (clean readings only).</dd>
<dt><code>limit</code> and <code>cursor</code></dt>
<dd>Up to 1,000 readings per page, 500 by default. For the next page, pass back the <code>next_cursor</code> you received.</dd>
</dl>
--- p 64-64
<p dir="auto">Here is one reading from Gannet Point, asked for with <code>?from=2026-11-14T09:40:00Z&amp;limit=1</code>:</p>
--- pre 66-83
<pre><code class="language-json" data-lines="3,7-9" data-title="200 OK">{
  "station": "LH-04",
  "next_cursor": "MjAyNi0xMS0xNFQwOTo1MDowMFo",
  "readings": [
    {
      "time": "2026-11-14T09:40:00Z",
      "qc": "flagged",
      "flags": ["spike:do_mgl"],
      "do_mgl": 9.4,
      "temp_c": 12.6,
      "sal_psu": 33.8,

--- p 85-85
<p dir="auto">Line 3 is your bookmark for the next page. Lines 7 to 9 show a flagged reading: oxygen jumped 1.5 mg/L in ten minutes, more than the spike rule allows, so the value is published with a flag instead of quietly dropped. Whether to trust it is your call.</p>

--- h3 91-91
<h3 dir="auto" id="rust">Rust</h3>
--- p 93-93
<p dir="auto">Add <code>reqwest</code> with the <code>blocking</code> and <code>json</code> features, and <code>serde</code> with <code>derive</code>.</p>
--- pre 95-114
<pre><code class="language-rust" data-lines="9-14" data-numbers="1" data-title="examples/latest.rs">use serde::Deserialize;

#[derive(Deserialize)]
struct Reading { time: String, temp_c: f64, do_mgl: f64, qc: String }
#[derive(Deserialize)]
struct Latest { station: String, reading: Reading }

fn main() -&gt; Result&lt;(), Box&lt;dyn std::error::Error&gt;&gt; {
    let latest: Latest = reqwest::blocking::Client::new()
        .get("https://api.tidewell.example/v2/stations/LH-04/latest")
        .header("X-Tidewell-Client", "latest-example/1.0")
        .send()?
        .error_for_status()?
        .json()?;
    let r = latest.reading;
    println!("{} {}: {} °C, {} mg/L ({})", latest.station, r.time, r.temp_c, r.do_mgl, r.qc);
    Ok(())
}
</code></pre>
--- p 116-116
<p dir="auto"><code>error_for_status</code> turns a 4xx or 5xx answer into an error, so a typo in the station id fails loudly instead of printing nonsense.</p>
--- h3 118-118
<h3 dir="auto" id="python">Python</h3>
--- pre 120-133
<pre><code class="language-python" data-title="latest.py">import os
import requests

headers = {"X-Tidewell-Client": "latest-py/1.0"}
if key := os.environ.get("TIDEWELL_KEY"):
    headers["Authorization"] = f"Bearer {key}"

url = "https://api.tidewell.example/v2/stations/LH-04/latest"
resp = requests.get(url, headers=headers, timeout=10)
resp.raise_for_status()
r = resp.json()["reading"]
print(f"{r['time']}: {r['temp_c']} °C, {r['do_mgl']} mg/L ({r['qc']})")
</code></pre>

<h2 dir="auto" id="data-model">Data model</h2>
--- p 154-154
<p dir="auto">The API speaks in three objects and one short list of flags. A flag never replaces a value; it travels with it.</p>
--- pre 156-188
<pre><code class="language-mermaid">classDiagram
  direction LR
  class Station {
    +String id
    +String name
    +String gateway
    +latest() Reading
  }
  class Sensor {
    +String serial
    +String kind
    +Date calibrated
  }
  class Reading {
    +DateTime time
    +float temp_c
    +float sal_psu
    +float ph
    +float do_mgl
    +float hs_m
    +String qc
  }
  class QcFlag {
    &lt;&lt;enumeration&gt;&gt;
    spike
    flatline
    drift
  }
  Station "1" --&gt; "5" Sensor : carries
  Station "1" --&gt; "*" Reading : records
  Reading "1" --&gt; "0..*" QcFlag : flagged by
</code></pre>
--- h2 190-190
<h2 dir="auto" id="paging-through-history">Paging through history</h2>
--- p 192-192
<p dir="auto">Ninety days of one station is 12,960 readings, so history comes in pages. Keep asking until <code>next_cursor</code> comes back empty.</p>
--- pre 194-209
<pre><code class="language-mermaid">sequenceDiagram
  participant C as Your client
  participant A as Tidewell API
  participant S as Store
  C-&gt;&gt;A: GET readings, from Aug 17, limit 1000
  A-&gt;&gt;S: first 1000 rows
  S--&gt;&gt;A: rows
  A--&gt;&gt;C: 200, readings + next_cursor
  loop until next_cursor is null
    C-&gt;&gt;A: GET readings, cursor
    A-&gt;&gt;S: next 1000 rows
    S--&gt;&gt;A: rows
    A--&gt;&gt;C: 200, readings + next_cursor
  end
</code></pre>
