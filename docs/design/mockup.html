Live changes feed

The feed answers one question: what changed while I was looking elsewhere? It lists every file the watcher reports, keyed by path, so a file saved twelve times stays one entry that moves back to the top.

Note

Temporary files (*.tmp, ~$*, swap files) and build folders never reach the feed. The filter runs in the core, before events are batched.

#Event model

Events come from two sources. The file watcher reports single saves; the git-dir watcher reports operations such as checkout or rebase, which arrive as one bulk batch.

EventSourceFeedToast
createdwatchernew entryyes
modifiedwatcherupdated in placeyes
removedwatcherkept, struck throughyes
checkoutgit operationone collapsed entryno
ts 
// One batch per quiet period (150 ms), or at most every second.
type FsBatch = {
  changes: FsChange[];
  bulk: null | { count: number; reason: "gitOperation" | "large" | "overflow" };
  rescan: boolean;
};

#Grouping

Bursts of saves collapse into one entry and never produce more than one toast: while a burst lasts, the toast updates its counter in place instead of stacking.

Each save shows its own toast, so nothing is missed.

Follow mode (Ctrl+Shift+L) opens the latest changed doc at most once every three seconds, and never for a bulk batch.

The feed is only useful if it is quiet. If people stop looking at it, it has failed.

#Rollout

  • Reconcile with disk and drop duplicates
