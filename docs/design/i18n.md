# Languages (i18n)

TrailMark's interface comes in five languages: **English** (the source), **Português (Brasil)**, **Español**, **Deutsch** and
**简体中文** (Simplified Chinese).
This page explains how a language is chosen, how the strings are organized, how to add a language, the conventions each
translation follows, and how the Windows installer hands its language to the app.

## Choosing the language

Settings → **Language** offers *System default* followed by each language written in itself (English, Português (Brasil),
Español, Deutsch, 简体中文), so a person can always find theirs. The change applies at once, with no restart: the text on screen, the
dates and numbers, the key names in tooltips, the native dialogs and the labels the app draws inside documents (the copy
button of a code block, the title of a note) all follow.

- **System default** follows the operating system's list of preferred languages (`navigator.languages`) and picks the first
  one the app speaks, by its language part (`pt-PT` reads Portuguese, `es-MX` reads Spanish, and every Chinese tag,
  `zh-TW` and `zh-Hant` too, reads Simplified Chinese, the one Chinese the app has). When none matches, it is English.
- The choice is **app-wide**, not per project: it is kept by the backend in `settings.json` in the app's data folder, next to
  the recent-folders list. The file is read forgivingly: a value written by a newer version reads as "not chosen" and
  unknown keys survive a write.
- A missing `language` key means "not chosen yet". Picking *System default* is a choice and is stored as `"system"`.

## Where the strings live

| What | Where |
| --- | --- |
| English strings (source of truth, defines the keys) | `src/lib/i18n/en.ts` |
| Other languages | `src/lib/i18n/ptBR.ts`, `es.ts`, `de.ts`, `zhCN.ts` |
| Language list, names, matching a system language | `src/lib/i18n/locales.ts` |
| Reactive current language | `src/lib/i18n/language.svelte.ts` |
| `t()`, `tn()`, `formatNumber()`, `joinList()`, `keys()` | `src/lib/i18n/index.ts` |
| Wording backend errors and document notes | `src/lib/errors.ts` (`errorMessage`, `noteText`) |

- Every user-facing string goes through `t("key", { name: value })`. Placeholders are `{name}`.
- Plurals come in pairs, `key.one` and `key.other`, read with `tn("key", count)`; `{n}` is filled with the count. The form is
  chosen with `Intl.PluralRules` for the current language (pt-BR reads zero as plural, see below). A language needs the forms its rules use for ordinary counts. The
  `many` category that Spanish and Portuguese have for exact millions reads as `.other`. A count of exactly 1 always reads
  `.one` when the table has it, whatever CLDR says. Chinese has no plural forms (every count is `other`), yet its `.one` keys
  exist (the key-parity test needs exactly English's keys) and are used for 1; most carry the same text as `.other`, and
  a `.one` may name the item where `.other` can only count them ("将 {name} 移到回收站？").
- `t()` reads the reactive current language, so a template that calls it redraws when the language changes. A string saved
  in a variable (a toast already shown) keeps the language it was made in.
- Numbers are written with `formatNumber()` (`1,200` or `1.200`). Relative times ("5 minutes ago", "vor 5 Minuten") come from
  `Intl.RelativeTimeFormat` (with a space put between a digit and Chinese text, as the rest of the Chinese table does); dates from `Intl.DateTimeFormat`. The clock stays 24-hour in every language. A date and a time
  are formatted in one call (`dateTime()` in `time.ts`), so the language decides what goes between them (`Oct 1, 08:15`, but
  `10月1日 08:15`). Never join a date and a time with a hard-coded comma.
- Lists and strung-together sentences take their separator from the language: `joinList()` reads `list.separator` (`, ` or
  Chinese `、`) and `list.sentences` is the semicolon between notes (`; ` or `；`). Do not write `.join(", ")` in UI code.
- Key names inside tooltips and menus go through `keys("Ctrl+Shift+O")`, which writes them as the language's keyboards do
  (`Strg+Umschalt+O` in German, `Ctrl+Mayús+O` in Spanish). The shortcuts themselves are matched by key position and never
  change. Strings that mention a shortcut inline carry the local key names in their text.

## Adding a language

1. Add the language to `LOCALES`, `LANGUAGE_NAMES` (written in itself) and `INTL_TAGS` in `locales.ts`, and teach
   `matchLocale` which system language tags map to it.
2. Copy `en.ts` to a new file, translate every value, and end it with `satisfies Messages` so the compiler reports a missing
   or extra key. Register the table in `MESSAGES` in `index.ts`.
3. If its keyboards name keys differently (Ctrl, Shift, Enter, Del), add them to `KEY_NAMES` in `index.ts`.
4. Add the language to the backend list: `Language` in `src-tauri/src/session/app_settings.rs` (its serialized form is the
   code used in `LOCALES`).
5. Windows installer: add the NSIS language to `bundle.windows.nsis.languages` in `src-tauri/tauri.conf.json` and its LCID to
   `src-tauri/installer/hooks.nsh`, and extend the test `the_installer_writes_exactly_the_codes_the_app_reads`. The same file
   holds the installer's own wording for the "Open with TrailMark" entries (`LangString OpenWithMenuLabel`, `OpenWithTypeName`,
   `OpenWithMenuOption`, `OpenWithAssocOption`, one line per language id): add the new language to each, and to `menu_label` and
   `type_name` in `src-tauri/src/shell_integration/entries.rs`, which the test `the_installer_writes_what_the_app_writes` compares.
6. Run `npm run check`. `src/lib/i18n/i18n.test.ts` fails when a table has a missing or extra key, when a placeholder
   differs from English, when a value is empty, when a long sentence was left in English, or when a shortcut names another
   key than the English string.
7. Look at the result at the default panel widths and at the 900 x 600 minimum window, in light and dark. `npm run dev:mock`
   runs the UI in a browser against a fake backend, and `?lang=de` (any language code) picks the language for that run. Long
   words (German especially) are the usual cause of clipped labels: shorten the wording first; where a label cannot fit, give it
   an ellipsis and a tooltip.

## Conventions per language

Keep the same word for the same thing everywhere (the tests do not check this; reviewers do). Product name (`TrailMark`),
file names, Markdown and code snippets, and version numbers are never translated. Git terms that developers say in English
(merge, rebase, cherry-pick, revert, bisect, commit, branch, HEAD, worktree) stay in English.

**Português (Brasil).** Impersonal or imperative wording; no formal address. Terms as Brazilian software uses them: Salvar,
Desfazer, Excluir, Lixeira, Área de transferência, Pasta, Arquivo, Caminho, Configurações, Pesquisar (all docs) and Localizar
(in the page), Explorador, Estrutura (outline), Fonte (the Source editor), Alterações, Acompanhar (follow). *Tags* stays *Tags*. Zero takes the
plural ("0 arquivos"), as Brazilian usage has it; CLDR's rule would make it singular, so `pluralCategory` overrides it for
pt-BR only.

**Español.** One neutral Spanish for Latin America and Spain. Labels use the infinitive (Abrir carpeta, Guardar), messages are
impersonal (No se pudo guardar), and the few hints that address the person use the *tú* imperative in its neutral form
(Presiona, Haz clic, Suelta). No *usted*, no *vosotros*. Terms: Etiquetas (tags), Esquema (outline), Papelera de reciclaje,
Portapapeles, Configuración, Agregar (not Añadir), Eliminar, Cambiar nombre, Código fuente (Source editor).

**Deutsch.** No *Sie* and no *du*: labels are nouns or infinitives (Ordner öffnen, Speichern), messages are impersonal
(Datei konnte nicht gespeichert werden), hints use the infinitive (Zum Ändern ziehen). Keys are named as on German keyboards:
Strg, Umschalt, Entf. Terms: Gliederung (outline), Papierkorb, Zwischenablage, Einstellungen, Quelltext (Source editor), Verfolgen
(follow), Seit dem letzten Besuch. Nouns are capitalized, including *Worktree* and *Tags*.

**简体中文.** Plain, concise wording as mainstream desktop software uses it; labels carry no pronoun, and the few hints that
address the person say *你* (never *您*). Sentences use Chinese punctuation (，。：？ and full-width parentheses and quotation marks
“ ”); key combos, paths, code and the `...` of a label that opens a dialog stay ASCII. A space separates Chinese from Latin letters
and digits. Keys keep their English names (Ctrl, Shift, Enter, Del), so `KEY_NAMES` has no entry. Terms: 文件 / 文件夹 / 文档
(file / folder / document), 资源管理器 (Explorer), 大纲 (outline), 标签 (tags), 更改 (changes), 搜索 (search all docs) and 查找 (find in
the page), 批注 (comments), 描述 (description), 基准 (baseline), 智能体 (agent), 跟随 (follow), 源码 (Source editor), 可视化 (Visual), 回收站, 剪贴板, 设置, 自上次访问
(since last visit). Of the Git terms, *merge*, *commit* and *branch* are written 合并, 提交 and 分支 as Chinese developers' tools do;
*checkout*, *rebase*, *cherry-pick*, *revert*, *bisect*, *HEAD* and *worktree* stay in English. Every Chinese tag (`zh-TW` too) reads
Simplified Chinese: there is no Traditional Chinese table yet.

## Messages that come from the backend

The backend never sends prose for the UI to show as it is:

- **Errors** carry a stable `kind` plus optional blanks: `subject` (a path or a name), `detail` (diagnostic text from the
  system or a library, shown as it is after the UI's own sentence) and `reason` (a code that narrows `invalidName`). The UI
  words each kind with an `error.<kind>` string (or an existing string with the same meaning). A kind without words, or a
  sentence whose blank is missing, falls back to the backend's English text, so a newer backend never shows an empty message.
- **Document notes** (an odd encoding, a rendering fallback) are codes (`utf16Le`, `invalidUtf8`, `deepNesting`...) worded by
  `note.<code>` strings.
- Left in English on purpose: the comments TrailMark writes into the files of a project it initializes (`.trailmark/config.toml`,
  `meta.toml`), because those files are shared between people; and diagnostic text such as the operating system's own messages
  and libgit2's repository errors.

## The Windows installer

The NSIS installer shows a language dialog (English, Portuguese (Brazil), Spanish, German, Simplified Chinese); it preselects
the language of the system when it is one of the five and falls back to English. The MSI stays English only.

1. After the files are installed, `src-tauri/installer/hooks.nsh` (`NSIS_HOOK_POSTINSTALL`) maps the installer's language to the
   app's code (`en`, `pt-BR`, `es`, `de`, `zh-CN`; the Windows language ids are 1033, 1046, 3082 or 1034, 1031 and 2052) and
   writes it to `HKCU\Software\TrailMark\Language`.
2. When the app starts and no language has been picked in Settings, it reads that value; with no value, it follows the system.
3. **A choice made in the app always wins.** The registry value only seeds the first run. An update (the installer's
   update mode, `/UPDATE`) does not replace a value that is already there, and neither the registry nor an update ever changes
   `settings.json`.
4. Uninstalling with *Delete the application data* ticked removes the registry value; an update's uninstall step keeps it.

Reading the registry is Windows only; on macOS and Linux there is no installer language and the app follows the system.

**Words the installer and the app write into the registry.** The "Open with TrailMark" entries of the file manager (see
`docs/design/v0.2.md`, section 14) carry text that the operating system shows, so it cannot come from the UI's string tables:
the menu entry ("Open with TrailMark", "Abrir com o TrailMark", "Abrir con TrailMark", "Mit TrailMark öffnen", "用 TrailMark 打开") and the name of
the file type ("Markdown document" and its translations). The installer writes them in the language it ran in; the app writes
them in the language of the interface when the person switches the entries on in Settings, and rewrites them when the language
changes (`refresh_shell_labels`). An update keeps the text already in the registry, so it never undoes a change made in the app.
The two options on the installer's welcome page use `LangString`s of their own in `hooks.nsh`, in the same five languages. The
file is saved as UTF-8 with a byte order mark, which NSIS needs to read the accents and the Chinese.
