# v0.5.2 design: pictures, sound and video as files

A project folder holds more than Markdown: screenshots, logos, diagrams, recordings of a session, a demo video. Until now
opening one of them showed "This file can't be shown here", with a button for the editor command. They are part of the
project, so they are now files like the others: they open in the pane, they are found by name, and anything the pane cannot
show can go to the program the system has for it.

**Principles**
- **Show it where you are reading.** A picture or a recording opens in the document pane from the Explorer, Quick open, search,
  a link or the feed, and a document can play a recording in place.
- **Only the open folder.** Files are served from the project (and the files next to a loose file), through the same path check as
  every other file. Nothing outside, no `..`, no link that leaves.
- **A click never runs a program.** Opening a file with the system's application is allowed for documents, pictures, sound,
  video and the like, and refused for programs and scripts.
- **Nothing is read whole that does not have to be.** A film is cut into parts as it plays.

## 1. The viewer

`DocumentView.kind` has three new values, `image`, `audio` and `video`. The backend decides by extension and reads only the size
and time of the file (`render::asset_view`); the pane draws the file itself from the asset scheme. The header and the status
bar use what the webview learns once it has decoded the file.

**Images** (png, jpg, jpeg, gif, webp, avif, bmp, ico, svg)
- Fitted to the pane by default. Fitting never enlarges: a 16 px icon shows at 16 px, and `Ctrl+=` enlarges it.
- A click on the picture, or the percentage button in the bar above it, toggles 100% and fit. `Ctrl+=` and `Ctrl+-` step through
  5, 10, 25, 33, 50, 67, 75, 100, 125, 150, 200, 300, 400, 600, 800 and 1600% (from the fitted scale, when fitted); `Ctrl+0` goes
  back to fit; `Ctrl` + wheel zooms. The middle of the picture stays in the middle. The status bar shows the percentage in
  place of the text zoom.
- A checkerboard (tokens `--checker-a` and `--checker-b`, with a dark pair) sits behind transparency.
- The header says `800 × 450 px · 312 KB`; the chip is empty of pixels until the picture is decoded.
- SVG is an `<img>`: no script runs, nothing is inlined, the response carries a sandboxing `Content-Security-Policy` for the day it is
  opened as a document.
- When the file changes on disk the document store reads it again (as it does for documents); the picture's address carries the
  file's time (`?v=`), so the webview fetches it again, and the zoom is kept.

**Sound and video** (mp3, wav, ogg, oga, opus, flac, m4a, aac, weba; mp4, m4v, webm, ogv, mov)
- The native `<audio controls>` and `<video controls>`, `preload="metadata"`. The header says how long it plays (and the pixels of a
  video). A bar under the player has **Open with default app**.
- The window plays what its codecs allow. Other formats of the same kinds (wma, aif, mka; mkv, avi, wmv, flv, mpg, 3gp) are known
  too, so they are listed, found by name and opened by the same pane, where the player's `error` shows "This file can't be played
  here" with **Open with default app** and **Show in file manager**. A codec that is missing from a format that normally plays
  (an HEVC `.mov`) fails the same way.
- Audio and video have no editing: the Read | Visual | Source switch is not shown for them.

## 2. Serving files safely

The custom scheme `tmasset` already served images; it now serves the three kinds.
- **Scope.** The request path goes through `Vault::resolve`: no absolute paths, drive letters, `..` above the root, alternate data
  streams, and a real location (after symlinks and junctions) outside the root is refused. A closed folder is never served. In
  Simple mode and for a loose file only the files next to the file are served. The built-in `asset:` protocol is not used: its scope
  can only grow, and a test asserts that it is not enabled.
- **Only these kinds, by the name of the file itself.** A path whose extension is not a picture, sound or video is `403`, so no
  document, source file or secret in the folder can be read through it. The check is made twice: on the name that was asked for and on
  the name of the file it resolves to once links are followed. A link `a.png` that points at `.env` is not a picture and serves
  nothing; a link between two pictures is served as the one it leads to (its type comes from the real name).
- **Ranges.** `Range: bytes=a-b`, `a-` and `-n` are answered with `206`, `Content-Range` and `Accept-Ranges: bytes`; a start past the
  end is `416`; an unreadable header is ignored, as the HTTP rules say. An answer carries at most 4 MiB, so a request for
  `bytes=0-` of a 4 GB file reads 4 MiB, and the player asks for the rest as it plays. Without a `Range` header a file up to 32 MiB
  is answered whole and a bigger one starts with its first part. A picture is read whole up to 32 MiB. A whole-file answer reads
  at most the size that the limit was checked on, so a recording that grows meanwhile cannot make it longer.
- **Headers.** `nosniff`, `no-cache`, and a sandboxing `Content-Security-Policy`.
- **CSP of the page.** `media-src 'self' tmasset: http://tmasset.localhost https:` (the same sources as images, minus `data:`).
- **The watcher** already compares large files by size and time only, so a film changing on disk does not stall it.

## 3. Open with default app

A button on the pane of any file the app cannot show (binary, too large, unplayable), an item in the Explorer's context menu for
every file except a Markdown document, an item in the header's menu for those files, and a command. It is separate from **Open in
external editor**, which runs the editor command from the settings.

**Refused, not confirmed.** The files of a project are often written by an agent or arrive with a clone, so a program or script that
shows up in the folder is exactly what must not run from a click. A confirmation names the file, and people click through
confirmations; the refusal cannot be clicked through, and the person who does mean to run it has **Show in file manager** (the toast
offers it) and their terminal. The refusal names the type (`.ps1`), so it explains itself.

The check (`media::open_policy`) is made on the backend, on the real file:
- by extension, lower-cased. A program is known by either spelling of its name, as written and without the dots and spaces that end
  it (`evil.exe.` is `evil.exe` to Windows), so `invoice.pdf.exe` and `evil.exe ` are refused and `setup.exe.txt` is a text file.
  Only Windows ignores those characters: on macOS and Linux `README.md.` is a file without an extension, so it gets no exemption
  (below), and an extension is read as written wherever a file is served;
- the list is programs and installers (`exe msi com scr pif msix appx appinstaller vsto jar dll cpl msc chm ...`), shortcuts and
  files that open something (`lnk url scf website rdp wsb udl theme themepack webloc inetloc fileloc afploc *-ms ...`), scripts (`bat
  cmd ps1 vbs vbe js jse wsf wsh hta reg sh bash zsh command tool py pyw pyzw rb rbw pl ahk au3 scpt ...`), macOS and Linux bundles
  and packages (`app pkg dmg deb rpm appimage desktop workflow terminal`), Access databases (`mdb accdb mde accde ade adp`) and
  documents that hold macros (`docm xlsm pptm ...`);
- any extension that starts with `{`: a class ID that Windows reads as a shell object whatever the file is;
- on Windows, every type of `%PATHEXT%`, read when it is asked, because the person can add to it (`.PY`, `.PL`);
- **the older Office formats** (`doc dot xls xlt xla xlsb ppt pot pps`) are refused too. Their names do not say whether a file holds
  macros, so they are treated like `docm` and `xlsm`. It costs one click: **Show in file manager** is in the refusal's toast, and the
  newer formats (`docx xlsx pptx`), which cannot hold macros, open as ever. The wording of the refusal names the kind of file
  and says "programs, scripts or documents that can run code";
- on macOS and Linux a file with an execute permission is a program too, unless its name as written ends in a document, picture,
  sound or video extension (a drive from Windows often gives every file that permission);
- the path is resolved first, so a link named `notes.txt` that points at a program is judged by the program.

The system's handler is then asked through the opener plugin, with no capability for the webview to open paths itself.

## 4. In documents

`video`, `audio` and `source` are in the sanitizer's allow list with `src`, `controls`, `loop`, `muted`, `poster`, `width`, `height`,
`preload` and `type`. `autoplay`, event handlers and styles are dropped; `controls` is always set and `preload` is forced to
`metadata`, so a document with twenty films reads twenty headers, not twenty films. `data:`, `blob:`, `file:` and script URLs in
`src` and `poster` are dropped. A relative `src` or `poster` is resolved against the document (like an image) and loaded through
the asset scheme after the block is in the page, so the webview never asks the app's own origin for it; a web address is left to
the webview and the `https:` source. A link to a media file resolves like any link and opens in the pane. The link scanner knows
`poster`, so a move or rename rewrites it.

## 5. The Explorer filter, Quick open, Search everywhere

- A fourth content category, **Audio and video** (`media`), next to Images. *Docs and assets* includes it, under the rules images have:
  next to a document (same folder or the one above), in a folder named like `assets`, `images`, `img`, `media`, `attachments`,
  `screenshots`, `figures`, `diagrams`, `pictures`, `audio`, `sounds`, `music`, `recordings`, `video`, `videos`, `movies`, `clips` or
  `screencasts`, or linked from a document (the backend's list of used files now includes media and `<video>` / `<audio>` sources and
  posters). A hidden folder still hides its files. A custom filter without the box hides them.
- The tree and the lists have an icon each for documents, pictures, sound and video.
- Quick open and Search everywhere list pictures and media by name whatever the filter hides, and keep the "+N hidden files match" row
  for everything else.

## 6. Folders in Quick open and Search everywhere

Reaching a folder deep inside a project took the Explorer. A path typed in Quick open (`Ctrl+P`) matched the files in it but never the
folder, and Search everywhere only listed files, sections, tags and commands.

Now the folders of the Explorer (the tree after the filter) whose path has the words are listed after the files, with **Reveal in
Explorer** at the end of the row, in the Files scope of the box and as a group of three in All. Enter opens the folders above it,
scrolls to it, opens it and puts the keyboard focus in the Explorer, so the arrow keys go on from there. Nothing is listed until
something is typed; a folder has no tags to search by, so a `tag:` filter lists files only; the Notes window has no folders.
