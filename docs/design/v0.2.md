# TrailMark v0.2: design addendum

Extends `wireframes.md` (MVP). Same legend, tokens, Lucide icons; all strings via `t()` (keys in §10).
New legend: `{tag}` app tag chip, `{tag}f` tag from frontmatter (locked), `*` unread dot, `|~` unsaved-block bar,
`[Visual|Source]` segmented switch. Scope order: tags, outline, editing, unread, code refs, commits.

## 0. What changes in the existing shell

- **Activity bar**: `[F]` Explorer, `[S]` Search, **`[#]` Tags (new)**, `[L]` right panel, `[T]`, `[*]`.
- **Right panel header** gets the segmented switch reserved in the MVP: `Changes | Outline | Commits`.
  Changes = today's Live changes + Since last visit. A 6px accent dot on `Changes` when events arrive while another tab
  is shown (same rule as the activity-bar dot). Tab choice persists per project.
- **Doc header**: the `[E]` slot becomes `[Edit]` (text button). "Open in external editor" moves to the `[:]` menu
  (Ctrl+Shift+E unchanged). New `[:]` items: Edit tags and description (T), Images in this doc, Mark as unread.
- **Doc meta strip** (new): one quiet row at the top of the reading column, above the frontmatter card, scrolls with
  the doc. Holds the description and tag chips. Hidden when the doc has neither (then `T` or the menu opens the editor).

## 1. Tags and descriptions (hybrid)

```
+---+--------------------------------------------------------------------------------------------------------+
|[F]| <- ->  docs / specs / live-feed.md  M   saved 12s ago                             [@] [Edit] [:]      |
|[S]|--------------------------------------------------------------------------------------------------------|
|[#]|        How the live feed groups watcher events into rows.                       (description, muted)   |
|[L]|        {feed}f  {watcher}f  {spec}  {needs-review}  [+]                                                |
|   |        +--------------------------------------------+                                                  |
|   |        | status: draft   updated: 2026-10-13        |   (frontmatter card; `tags:` moved to the strip) |
|   |        +--------------------------------------------+                                                  |
|   |        Live changes feed                                                                               |
```
**Chips**. App tags: 10% tint background + 6px color dot, text in `--text`. File tags: same look plus a Lucide
`file-text` glyph at 12px and tooltip "From the file's frontmatter. Edit the file to change it." The same tag in both
places shows once, as a file tag. Click a chip = open the Tags view filtered by that tag. `[+]` opens the popover.
**Colors**: 8 muted hues (no accent, no git colors), picked by a stable hash of the tag name, so every machine and
every teammate sees the same color. No color picker in v0.2.

**Popover** (from `[+]`, a chip's context menu, the `[:]` menu, or `T` while reading):
```
+--------------------------------------------------------+
| Description                                            |
| [How the live feed groups watcher events._  ]  47/120 |
| Tags                                                   |
| {feed}f {watcher}f {spec x} {needs-review x} [wat_   ] |
|   +------------------------------------------+         |
|   | watcher-api      4 files                 |         |
|   | Create tag "wat"                         |         |
|   +------------------------------------------+         |
| Saved in TrailMark, not in the file.         [Done]    |
+--------------------------------------------------------+
```
- Edits apply immediately (metadata is not the document; no save step). Done or Esc closes. Enter or comma adds the
  typed/highlighted tag; Backspace on an empty input removes the last app tag; file tags have no `x`.
- Autocomplete: existing tags (app + file) fuzzy-matched, ranked by file count; last row "Create tag "x"".
- Normalization: trimmed, lowercased, inner spaces become `-`, max 40 chars; `/` is allowed text (no nesting yet).
  Description: one line, 120 chars, newlines stripped.
- The footer names the store; with `.trailmark/`: "Saved in .trailmark/meta.toml (shared with the project)."
- Works for any file type, including binary and too-large states (the strip sits above the notice).

**Storage**. `.trailmark/meta.toml` when initialized (committable, so teams and agents can read it), else AppData per
project. Keyed by vault-relative path: `[files."docs/specs/live-feed.md"] tags = [...] description = "..."`.
A `renamed` change moves the entry; entries of missing files are kept (a checkout may restore them) until Clean up.
Writes are debounced 300ms and ignored by the watcher; initializing `.trailmark/` moves the AppData metadata there.

**Tags view** (`[#]`, Ctrl+Shift+T):
```
+------------------------------------+    +------------------------------------+
| TAGS                     [Any|All] |    | TAGS                               |
| [filter tags_                    ] |    |                                    |
| [x] (o) spec                    12 |    |   No tags yet.                     |
| [x] (o) needs-review             3 |    |   Press T on a doc to tag it, or   |
| [ ] (o) feed  (file)             5 |    |   add `tags:` to its frontmatter.  |
| [ ] (o) watcher                  4 |    |                                    |
|     Untagged                   212 |    |                                    |
|------------------------------------|    +------------------------------------+
| 2 FILES  spec + needs-review       |
| * live-feed.md          docs/specs |
|   How the live feed groups...      |
|   plan.md                   (root) |
|------------------------------------|
| 3 missing-file entries  [Clean up] |
+------------------------------------+
```
- Tag list sorted by count; "(file)" marks tags that exist only in frontmatter. Click a tag = select only it;
  Ctrl+click or Space = toggle (multi-select). `Any|All` sets OR/AND (default All). Untagged is a pseudo-tag.
- File list below: name, folder, description as a muted second line, unread dot, git badge. Click/Enter opens.
- Tag context menu: Rename tag..., Remove from all files (app tags only; file tags show these disabled with the
  "Edit the file to change it" hint). Rename into an existing tag merges, after a confirm with the file count.
- States: no tags (above); filter with no match "No tags match 'x'"; selection with no files "No file has all of
  these tags. Try Any."; `meta.toml` unreadable (e.g. merge conflict): banner "Can't read .trailmark/meta.toml
  (line 12). App tags are read-only until it is fixed. [Open file]", file tags still listed.

**`tag:` filter** in Search (Ctrl+Shift+F) and Quick open (Ctrl+P): `tag:spec` tokens (AND when repeated) filter
results; the rest of the query searches as before. Typing `tag:` opens the same tag autocomplete inline. In Ctrl+P a
query that is only `tag:x` lists every file with that tag, sorted by recency. A matched tag renders as a chip in the
input row. Unknown tag: "No tag 'x'. Tags: spec, feed, watcher...".
**Descriptions show** in: the tree tooltip (path, description, tags), the Quick open row (muted second line, also
matched by fuzzy at the lowest rank), and the Search file-group header (muted subline).

## 2. Outline (right panel, `Outline` tab)

```
+---------------------------------+
| Changes  [Outline]  Commits  [>]|
| Depth: [2] [3] [All]            |
|---------------------------------|
| v Live changes feed             |
|     Event model               o |   o = section has a live-changed block
|   | Grouping                    |   | = current section (accent-muted bar, semibold)
|   > Rollout                     |
| > Appendix                      |
+---------------------------------+
```
- Built from the rendered doc's headings (`data-sourcepos`), h1-h6, indented 12px per level. Depth default 3.
- **Current section**: the last heading above the top-third line of the viewport; updates on scroll (rAF-throttled);
  the outline auto-scrolls to keep it visible.
- Click/Enter: scroll the heading to the top (8px offset), 1.5s `--mark` tint like a search hit; no history entry.
  Left/Right collapse/expand; chevrons per node; collapse state is per doc for the session only.
- Live reload rebuilds the outline keeping collapse state by heading text; a dot `o` (accent) marks sections whose
  blocks changed, cleared with the gutter bars. In edit mode it rebuilds 300ms after typing stops.
- Ctrl+Alt+O: show the Outline tab (opens the right panel if collapsed); pressed again, returns to the previous tab.
- Simple mode has no right panel: Ctrl+Alt+O opens the outline as a popover anchored to the header (same list).
- States: no headings "This document has no headings."; non-Markdown "Outline is available for Markdown documents.";
  no doc "Open a document to see its outline."; more than 1,000 headings: first 1,000 + "Showing 1,000 of 1,312".

### Implementation notes: Outline (2026-10-14, `feature/outline`)
- Built as specified with the Decisions applied: **no depth control** and **no Commits tab**, so the switch is `Changes | Outline`.
  The views are one list (`RIGHT_TABS` in `rightPanel.ts`), so a third tab is one entry there plus its panel. The header is the
  tabs and the collapse button; the live status and the "Docs only" chip moved to a row under the tabs, in the Changes view
  (the title "Live changes" is gone: the tab says it). The tabs are a WAI-ARIA tab list (Left/Right move between them).
- Pure logic in `outline.ts` (tested): `buildOutline` turns the top-level blocks into the tree, `visibleRows`/`visibleAncestor`
  apply the collapse state, `currentHeading` finds the section being read, `navigate` is the keyboard, `CollapseMemory` keeps the
  collapse state. `DocView` reads the DOM (`dom/outlineDom.ts`) after **every** render, fresh or live, and reports to the
  `outline` store; the panel and the popover only show it (`OutlineList.svelte`, one component for both).
- Only **top-level** headings count (not one inside a list item or a quote), the same blocks the block diff and "copy with
  reference" use. The indent is 12 px per **nesting level**, not per heading level: a document that starts at h2, or skips from h2 to
  h4, is not indented by the gap.
- **Current section**: a binary search over the heading tops at the top-third line, once per animation frame, so a 1,000-heading
  document costs about ten measurements per frame. Two refinements to "the last heading above the line": at the very bottom of the
  page the last heading that is on screen counts (it can never reach the line), and a heading chosen in the outline stays current
  until the reader scrolls by hand (near the end of the page it cannot reach the top, so the scroll alone would highlight its
  neighbour). When a collapsed heading hides the current one, the collapsed heading carries the bar.
- Click or Enter scrolls the heading to 8 px under the top and tints **the heading only** for 1.5 s (a search hit also tints the
  paragraph after it); it calls DocView directly, so there is no history entry. Focus stays in the list so the next key works.
- Collapse state is per document for the session (`CollapseMemory`, the last 64 documents), keyed by heading text; a text that
  repeats is numbered by order (so the first one keeps its plain key). A renamed heading starts open again.
- The accent dot: the blocks of a section that carry `.tm-changed` or a removed-blocks marker, so it lives exactly as long as the
  gutter bars (the next render replaces both). A **collapsed** heading shows the dot too when something below it changed, so it is
  not lost by collapsing.
- Ctrl+Alt+O (`toggleOutline` in `rightPanel.ts`): opens the panel on the Outline and moves the focus into the list; pressed again it
  returns to the tab that was showing before and puts the focus on the document (the list it was in is gone). The way back is not
  saved. The dot on `Changes` follows the activity-bar rule (a document changed), and is set whether the panel is open or collapsed.
- Session field `rightTab` (`"changes" | "outline"`, per project). Rust keeps it as an enum that reads an unknown or mistyped value
  (a newer UI wrote it) as `changes`, so the session survives; a save from before the Outline has no field and reads as `changes`.
- Simple mode: Ctrl+Alt+O toggles a popover under the header, right-aligned, closed by Esc, by choosing a heading or by the
  shortcut. Added beyond the spec: an "Outline" entry in the `[:]` menu, **in Simple mode only**, so a mouse user can find it.
- Collapse and resize labels, the activity-bar tooltip and the status-bar toggle now say "right panel" instead of "live changes".
  `live.title` is gone. The keys of section 12 that were cut are not created (`outline.tab`, `outline.depth*`, `panel.tabCommits`);
  the tab uses `panel.tabOutline`. New: `panel.label`, `panel.tabs`, `panel.tabChangesHint`, `panel.tabOutlineHint`, `panel.newChanges`,
  `outline.label`, `outline.changed`, `outline.untitled`, `menu.outline`.
- **Not built yet**: the rebuild 300 ms after typing in edit mode, because there is no editor yet. When it lands, call the same
  report with the headings of the Visual editor.
- The mock vault has `docs/design/outline.md` (levels 1 to 4, a skipped level, a repeated heading and a very long one; each save
  rewrites a paragraph under "Risks" and adds a section), `docs/design/long-outline.md` (1,312 headings, for the cut at 1,000) and two
  h3 sections in the live feed doc.

## 3. Editing (Visual + Source, block-preserving save)

**Promise to the user**: TrailMark rewrites only the blocks you changed; every other byte stays as the author (or agent)
wrote it. The UI makes this visible: blocks that will be rewritten carry an unsaved-block bar `|~` until saved.

```
+---+--------------------------------------------------------------------------------------------------------+
|[F]| <- ->  docs / specs / live-feed.md  M  (*) Unsaved      [Visual|Source]  [Save]  [Done]  [:]          |
|[S]| [Paragraph v] [B][I][S][<>] [link] [*-][1.][v-] ["] [table v] [{}] [img] [--]                  [...]  |
|   |--------------------------------------------------------------------------------------------------------|
|   |        {feed}f {spec} [+]                                                                              |
|   |        +-----------------------------------------------+                                               |
|   |        | status: draft            [Edit in Source]     |  frontmatter: locked atom, bytes kept         |
|   |        +-----------------------------------------------+                                               |
|   |        Live changes feed                                                                               |
|   |     |~ Bursts of saves collapse into one entry, and the toast_                                         |
|   |        +-----------------------------------------------+                                               |
|   |        | <div class="note">...</div>  [Edit in Source] |  raw HTML / Mermaid / math: locked atom       |
|   |        +-----------------------------------------------+                                               |
+---+--------------------------------------------------------------------------------------------------------+
| git: main   5 changed   Editing: Visual   Follow paused                                                    |
+------------------------------------------------------------------------------------------------------------+
```
**Enter / exit**
- Enter: `[Edit]`, `E` while reading (focus not in an input), or Ctrl+E. Default mode from Settings (Visual).
  Cursor lands on the block at the top of the viewport; scroll position is kept.
- If the doc is "writing..." (a burst in the last 10s): a header chip "Being written (last save 2s ago)" and the edit
  still opens; the conflict rules below protect the user.
- Exit: `[Done]`, Ctrl+E, or Esc (Esc first closes the slash menu, link popover or a table menu). Clean: back to reading
  at the same block. Dirty: an inline bar under the header, never a modal:
  "Unsaved changes in live-feed.md.  [Save] [Discard] [Keep editing]" (Enter = Save, Esc = Keep editing).
  The same bar appears when navigating away while dirty (tree click, link, back, Ctrl+P, Follow never jumps).
  Closing the window while dirty: native confirm with the same three choices.
- Ctrl+S saves (stays in edit mode). After save the header meta reads "Saved, 2 blocks changed" for 3s. First save
  ever shows a one-time hint: "TrailMark rewrites only the blocks you changed."
- Dirty indicator: `(*) Unsaved` in the header, a dot on the tree item, `* ` prefix in the window title.
- Read-only files or save failure: error bar "Can't save live-feed.md: access denied. [Retry] [Copy all]"; the buffer is
  kept. Binary, too-large and non-Markdown text files: `[Edit]` is disabled with a tooltip saying why
  (non-Markdown text files: "Edit in external editor"; JSON/XML editing is later).

**Visual mode (Milkdown Crepe)**. Reading typography and tokens unchanged; only a caret and the toolbar appear.
- Toolbar (sticky under the header, Visual only): block type (Paragraph, H1-H4), bold, italic, strike, inline code,
  link, bullet / numbered / task list, quote, table, code block (language picker), image, horizontal rule. Narrow
  widths fold the tail into `[...]`. Each button has tooltip + shortcut; active marks show pressed.
- Table menu: Insert table (3x3), and when the caret is in a table: add row above/below, add column left/right,
  delete row, delete column, delete table. Crepe's row/column handles stay, restyled with tokens.
- Slash menu: `/` at the start of an empty block lists block types with icons; type to filter, Up/Down, Enter, Esc.
- Link (Ctrl+K inside the editor): popover with text and target; the target autocompletes vault files (inserted as a
  relative path) and, after `#`, the headings of that file. Broken targets are flagged in the popover.
- **Locked atoms**: frontmatter, raw HTML, Mermaid, math, footnote definitions and any block the editor can't
  represent render read-only (rendered view + `[Edit in Source]`), are never re-serialized, and keep their bytes.
- Task checkboxes are clickable in Visual mode (changes that list block only).

**Source mode (CodeMirror 6)**: raw text, Markdown highlighting, code font, soft wrap at the reading measure, line
numbers in the gutter, current line in the status bar. No toolbar; Ctrl+B / Ctrl+I / Ctrl+K wrap the selection in
syntax. Saving writes the buffer as-is.
- Switching (`[Visual|Source]` or Ctrl+Alt+E) keeps unsaved work: Visual to Source serializes only edited blocks into
  the text, so Source shows exactly what Save will write; Source to Visual re-parses, and blocks whose text equals
  the original are untouched again. Caret maps to the same block.

**External changes while editing**
- Clean buffer: auto-reload into the editor, caret kept on the same block (by sourcepos), header meta "Reloaded from
  disk 10:42". No glow: live highlights pause in edit mode and do not replay on exit.
- Dirty buffer: conflict banner under the header; editing continues, but Ctrl+S opens the banner instead of writing.
```
+------------------------------------------------------------------------------------------------------------+
| (!) live-feed.md changed on disk at 10:42 while you were editing.                                          |
|     [Show diff]   [Reload theirs]   [Keep mine (overwrite)]   [Merge: both kept]                           |
+------------------------------------------------------------------------------------------------------------+
```
- Reload theirs: discards local edits (confirm only if more than 5 blocks are dirty). Keep mine: writes the buffer
  over the disk version. Merge (shown only when mine and theirs changed different blocks): applies my edited blocks onto
  the disk version; otherwise hidden. Further disk changes update the banner time; deletion on disk turns it into
  "deleted on disk while you were editing. [Save as new file] [Discard]".
- Show diff: replaces the doc area until closed (Esc), block-level, side by side, rendered (Source mode: raw text).
```
+--------------------------------------------------+--------------------------------------------------+
| ON DISK (theirs) 10:42                           | YOURS (unsaved)                                  |
|--------------------------------------------------+--------------------------------------------------|
|           - - - 6 unchanged blocks [show] - - -  |                                                  |
| ++ Bursts collapse into one entry.               | |~ Bursts of saves collapse into one entry, and   |
| ++ (new) Rollout checklist ...                   |    (absent)                                      |
|           - - - 12 unchanged blocks [show] - - - |                                                  |
|                 [Reload theirs]  [Keep mine]  [Merge: both kept]  [Close]                           |
+-----------------------------------------------------------------------------------------------------+
```
  Rows align by block (LCS, as the live diff); F7/Shift+F7 walk differences. Per-block picking is later.

**Images** (Visual: paste, drag onto the editor, or the toolbar `[img]` file picker; Source: paste/drop too)
- The file is written at once to `<doc folder>/assets/` (folder name and placement in Settings), name
  `<doc-stem>-YYYYMMDD-HHMMSS.png` for pasted data, slugified original name for dropped files, `-2`, `-3` on clash.
  Inserts `![](assets/name.png)` and opens a small alt-text field ("Describe the image", Enter/Esc skips).
- Setting "On paste: Save automatically | Ask for a name". Over 10 MB: confirm. Non-image drops on the editor:
  toast "Only images can be added here (PNG, JPG, GIF, WebP, SVG)". Drops outside the editor keep MVP behavior.
- Images are written before the doc is saved; discarding leaves orphans, which the manager shows.
- **Images in this doc** (`[:]` menu or toolbar `[img v]`), a popover list:
```
+-----------------------------------------------------------+
| IMAGES IN THIS DOC (3)                                    |
| [thumb] assets/live-feed-20261014-104201.png   84 KB  ok  |
| [thumb] ../shared/arch.svg                    12 KB  ok  |
| [ x ]   assets/old-diagram.png                 missing    |
| UNUSED IN assets/ (2)                                     |
| [thumb] assets/live-feed-20261014-103955.png  [Delete]    |
+-----------------------------------------------------------+
```
  Click a row: scroll to the image (or reveal in tree for unused). Unused = in this doc's assets folder and referenced by
  no Markdown file in the vault (uses the search index's link scan). Delete goes to the recycle bin. Remote URLs are
  listed as "external", never fetched. Empty: "No images yet. Paste or drop one while editing."

**New file** (Ctrl+N; tree context menu on a folder or file: New file..., New folder...)
- An inline name input appears in the tree under the target folder (selected folder, else the open doc's folder,
  else root), prefilled `untitled.md` with the stem selected. `.md` is added if there is no extension.
  Inline errors: "A file with this name exists", "Names can't contain \ / : * ? \" < > |". Esc cancels.
- Templates: if `.trailmark/templates/*.md` (or the AppData templates folder) has files, Enter shows a short picker
  "Blank, meeting-notes, spec..." (Blank first); placeholders `{title}` (from the file name) and `{date}`.
- Enter creates the file on disk (blank: `# {title}\n`), opens it in edit mode with the caret after the title.
- Simple mode: Ctrl+N asks for the name in a small dialog and creates the file next to the open one.

## 4. Unread markers ("changed since I last read")

- **Read** = the doc was open in a focused window and either the user scrolled it or it stayed visible 3s. Then its
  content hash is stored as "last read" (per project, `local/`, never committed). Saving your own edits marks it read.
- **Unread** = current hash differs from last read. On the first visit every existing file counts as read; files
  created later start unread. A live change to the open doc while the window is focused stays read; if the window is
  unfocused it becomes unread until the 3s rule passes again.
- Shown as a 6px accent dot `*` left of the name in: tree, Quick open rows, Search file groups, Tags view file list,
  Since last visit rows. Folders: name in semibold + dot when any descendant is unread; tooltip "3 unread".
- Actions: Explorer `[:]` "Mark all read" and "Show only unread" (filters the tree; empty result "All caught up.");
  folder context menu "Mark folder read"; doc `[:]` "Mark as unread"; Alt+U opens the next unread doc (feed order,
  then tree order) and says "All caught up." in a toast when none is left.
## 5. Clickable code references

- Detected in inline code and plain text (not in code blocks or existing links): `path/file.ext:42`, `:42:7`,
  `file.ext#L42`, `#L42-L50`. Resolution: vault root, then the doc's folder, then a unique file-name match in the
  index. Ambiguous: click shows a small list of candidates. Unresolved: left as plain text (no false links).
- Style: dotted underline in `--muted`, solid on hover. Hover tooltip: resolved path + "Open in editor at line 42".
- Click: Markdown targets open in TrailMark scrolled to the line (sourcepos) with the section tint; other files run the
  editor command template (Settings) with `{path}` (absolute, quoted as one argument), `{line}`, `{col}` (default 1),
  spawned without a shell. Empty template: OS default app, line ignored. Context menu: Copy path, Copy reference.
- Error: toast "Couldn't run 'code': not found. Set the editor command in Settings. [Settings]". The same template
  powers "Open in external editor" (line = the block at the top of the viewport).

The popover becomes sectioned and scrolls (max-height 70vh); each field shows its scope: (you) global or (project),
the latter stored in `.trailmark/config.toml` when initialized, else AppData.

## 8. Flows

**Tag and find**: open doc, `T`, type `rev`, Enter picks `needs-review`, Esc. Later Ctrl+P `tag:needs-review`
lists the files; or `[#]`, click `needs-review`, Ctrl+click `spec` (All) to narrow.
**Edit an agent's doc safely**: `E`, fix a sentence (its block gets `|~`), the agent saves meanwhile: banner. Show diff:
the agent changed other blocks, so Merge: both kept, then Ctrl+S ("Saved, 1 block changed"), Esc to reading.
**Catch up after coffee**: unread dots in the tree; Alt+U walks unread docs one by one; Commits tab shows what was
committed since the last-visit divider; click a doc in a commit to open it.

## 11. Flags, conflicts with the design system, recommended cuts

- **Shortcut clashes**: Ctrl+B (sidebar) and Ctrl+K (palette, reserved) mean bold and link while the editor has focus,
  as every editor does; sidebar stays on the activity bar and status bar toggles. Crepe's default inline code (Ctrl+E)
  is rebound to Ctrl+\` so Ctrl+E always toggles edit mode. Copy reference (Ctrl+Alt+C) loses to code block in the
  editor; use `[@]` there. Ctrl+Shift+O stays "Open file", hence Ctrl+Alt+O for Outline.
- **"One accent color"**: 8 tag hues add color as decoration. Kept muted (10% tint + small dot, text stays neutral),
  never accent or git hues. Simpler variant: one neutral chip style, no colors.
- **Chips are in a meta strip, not the header row**: the header is already full; the strip sits directly under it.
- **Command palette (Ctrl+K)** is still not designed; every new command lives in a menu or shortcut. Add it next.
- **Effort**: this is several days, not 1-2h. Ship in this order, each end to end: tags, outline, editing core
  (Visual + Source, save, dirty bar, conflict banner with Reload/Keep mine), unread, code refs, the rest.
- **Cut first** (in order): commit timeline (§6); Merge button and the side-by-side diff (keep Reload/Keep mine and a
  plain "Open both in external diff"); templates (blank only); image manager's vault-wide orphan scan (list used
  images only); link target autocomplete; outline depth control; Tags view Any/All (AND only); tag rename/merge.
- **Risks**: Crepe's block-to-sourcepos mapping for nested lists and tables needs round-trip tests on real agent docs
  before release; if a block can't be mapped, treat it as a locked atom rather than risk rewriting it.

## 13. Explorer filter (added 2026-10-14)

Opening a code repository shows every source folder; for reading, the user wants the docs and their companions.

```
EXPLORER                      [filter Docs and assets v]
+--------------------------------------------------+
| (o) Documents        .md .markdown .mdx .txt     |
| (o) Docs and assets  + images, JSON, YAML, TOML, |   default
|                        XML, CSV                  |
| ( ) Everything                                   |
| ( ) Custom...                                    |
|--------------------------------------------------|
| [x] Only assets next to documents                |
| [x] Hide folders with no visible files           |
+--------------------------------------------------+
...
Showing 52 of 1,204 files  [Show all]                  (tree footer, only when something is hidden)
```
- Presets are bundles of categories: Documents, Images, Data (JSON, YAML, TOML, CSV), XML, Text, Other.
  **Custom** = category checkboxes plus an optional advanced field of globs (`+*.sql`, `-archive/**`).
- **Only assets next to documents** (on by default; for Docs and assets and Custom, disabled for Documents and Everything).
  Images, data and XML files are companions of documents, not of code: `src-tauri/Cargo.toml`, `tauri.conf.json`,
  `icons/*.png`, `.github/workflows/*.yml` and `.vscode/*.json` have no business in a reading tree. With the rule on, such a
  file shows only if its own folder, or the folder above it, directly holds a document (Documents or Text category). So
  `docs/assets/logo.png` shows (`docs/` holds `.md` files) and the root `package.json` shows (the root holds `README.md`), while
  `src-tauri/` and `.github/workflows/` disappear. The project root counts as a file's own folder only, never as "the folder
  above": otherwise every first-level code folder would borrow the root's README. Explicit `+pattern` entries still win.
- **Hide folders with no visible files** (on by default) is what makes the tree useful in a code repo: `src/` and
  `src-tauri/` disappear, `docs/` and the root docs stay. Worktree roots follow the same rule.
- Nothing becomes unreachable: a hidden file opened by link, search, Ctrl+P or the feed appears in the tree, dimmed,
  while it is open. The footer always says how much is hidden and offers Show all (a temporary toggle).
- Quick open (Ctrl+P) uses the same filter and shows "+N hidden files match" as a last row that reveals them.
  Section search is Markdown-only already; the feed keeps its own "Docs only" toggle.
- The choice persists per project (session state). With `.trailmark/`, a project default can be committed in
  `config.toml` (`[tree] show = "docs-and-assets"`, `include = [...]`, `exclude = [...]`); the user's choice wins.
- Filtering happens in the UI over the already loaded tree (no Rust walk change); categories map extensions in one
  shared table (also used by the renderer registry where it overlaps).
- i18n keys: `filter.*`: title, documents, docsAndAssets, everything, custom, hideEmptyFolders, showingOf, showAll,
  hiddenMatches, categoryDocuments, categoryImages, categoryData, categoryXml, categoryText, categoryOther, advanced,
  advancedHint, invalidGlob.

### Implementation notes: Explorer filter (2026-10-14, `feature/explorer-filter`)
- Built as specified. Pure logic in `fileKinds.ts` (extension to category) and `treeFilter.ts` (presets, patterns, pruning); the
  filter in force is derived in `stores/filter.svelte.ts` from the saved choice, else the project default, else "Docs and assets".
- Presets: Documents = the Documents and Text categories; Docs and assets adds Images, Data and XML. Text is `.txt .text .rst .adoc .org`.
- Patterns are gitignore-style, case-insensitive, and apply in **Custom** only: no `/` matches a name at any depth, a `/` anchors at
  the project root, a trailing `/` means a folder's contents, a folder name also covers what is inside it, and the last matching
  entry wins. `*`, `**`, `?`, `[abc]` and `{a,b}` work. Entries are separated by spaces or commas. In a worktree they match the path
  inside the worktree.
- `[tree]` in `config.toml`: `show` picks the preset (default `docs-and-assets`); `include` and `exclude` become `+` and `-` entries,
  so a project with patterns opens as **Custom** with the preset's categories checked (every active rule is visible in the popover).
  `show = "custom"` starts from nothing: only `include` is shown. The config is read when the project opens.
- "Show all" is not saved; any change in the popover ends it. While it is on, the footer reads "Showing all N files [Use filter]".
- Quick open without a query lists recent files that pass the filter; "+N hidden files match" appears once something is typed and
  reveals the hidden matches (dimmed) for as long as the palette is open.
- **Only assets next to documents** (added after review; `TreeFilter.assetsNearDocs`, default true): the rule above, with
  `documentFolders()` listing the folders that directly hold a document and `fileTest()` applying it after the category check
  and before the patterns (so `+pattern` and `-pattern` still win, the last match first). A worktree root is a root: its
  files are judged against the worktree's own folders. On this repository (258 files) Docs and assets shows 32: the Markdown
  files, `docs/assets/*`, and the root `package.json`, `package-lock.json` and `tsconfig.json`. Consequence: a project whose
  images live in a first-level `assets/` folder with no document in it hides them until the box is unchecked or a
  `+assets/**` pattern is added.
- The saved filter is read leniently: a `show` this build does not know (written by a newer UI) reads as the default preset
  and keeps the rest; a filter that cannot be read at all reads as "none chosen". The session itself is never lost to it.
- Added i18n keys beyond the list above: `buttonLabel`, `hint`, `documentsHint`, `docsAndAssetsHint`, `categories`,
  `categoryDataHint`, `showingAll`, `useFilter`, `hiddenFile`, `noneVisible`, `assetsNearDocs`, `assetsNearDocsHint`.
- Not changed: the Rust renderer registry keeps its own format list (the category table is UI-side), and Search, the Tags view and
  the feed are not filtered.

## 15. Reading width (added 2026-10-14)

The reading column was capped at 760 px (`--measure`) or 1100 px (wide). Long text lines tire the eye, but tables, code
blocks and diagrams, which AI docs have plenty of, were squeezed.
- **Three widths**: Comfortable (760 px, default), Wide (1100 px), **Full** (the whole doc pane, with the usual side
  padding). The header/settings width control cycles through them; the session stores `width: "comfortable" | "wide" | "full"`
  (migrating the old `wide: boolean`), per project as today.
- **Breakout for wide blocks**: in every width, tables, code blocks, Mermaid diagrams, display math and images wider than
  the text measure may grow up to the pane width (minus padding), centred on the column; paragraphs, lists, headings and
  quotes stay at the measure. A block only breaks out when its content needs it (narrow tables stay at the measure).
  Horizontal scroll inside a block remains only when even the pane is too narrow.
- Find highlights, live-change glow, removed-block markers, the meta strip and the frontmatter card follow the text
  measure; broken-out blocks keep their glow and gutter bar aligned to the block.
- i18n: `width.comfortable`, `width.wide`, `width.full`.

Build order update: tags → Explorer filter → **reading width** → outline → core editor → unread → code refs → Open with TrailMark.

### Implementation notes: reading width (2026-10-14, `feature/reading-width`)
- Built as specified. `data-width` on `.main` drives the cap: Comfortable keeps `--measure` (760 px), Wide sets it to
  `--measure-wide` (1100 px), Full lifts the cap on the article, the meta strip and the loading skeleton. The pure rules
  (names, the cycle, the migration) are in `readingWidth.ts`.
- Session: `width` replaces `wide`. A save from before v0.2 carries `wide`: the UI migrates it (`true` becomes Wide, `false` or
  nothing becomes Comfortable) and never writes it again. Rust keeps both fields as `Option`s so nothing is lost on the way
  through: a `width` this build does not know (written by a newer UI) reads as unset, like the Explorer filter, and the session
  survives. The cycle is one control in three places: the status bar button, the `[:]` menu entry ("Reading width: Wide") and
  Ctrl+Alt+W (the shortcut is now `cycleWidth`); Settings shows the three as a segmented control.
- The breakout is CSS only, with no measuring script. `.doc-column` wraps the article as a size container, so `100cqw` is
  the pane's content width. A top-level `.table-wrap`, `.code-block`, `.diagram` or `.tm-wide` block is
  `width: max-content` (what its content needs) between `min-width: 100%` (the text measure) and `max-width: 100cqw`
  (the pane), centred with `left: 50%; translateX(-50%)`. A webview without container units keeps the text measure.
  "Needs room" therefore means the content's natural width: a table is as wide as its columns want to be, so a table with long
  prose cells also takes the pane (and wraps less); a narrow table or a short snippet stays at the measure.
- Only top-level blocks break out. A table or code block inside a list item, a quote or `<details>` keeps scrolling inside its
  parent. `.tm-wide` marks the paragraph of a lone image (or a linked image) when the block is enhanced, and the paragraph
  of a lone display formula once KaTeX has rendered it (so the raw TeX never flashes wide). Mermaid draws `width="100%"`, which
  has no size of its own, so the SVG gets the width of its `viewBox` as a pixel width (still capped at 100% of the figure).
- Glow and gutter bar belong to the block's own box, so they move with it; `.tm-removed` markers and `.md-body` paragraphs stay
  at the measure. Checked in the mock at Comfortable, Wide and Full, light and dark, with both side panels open and collapsed
  (no sideways page scroll in any), at zoom 70% to 130%, with find highlights and a live save. With both panels open at 1440 px
  the pane is narrower than the measure, so nothing can break out; collapse a panel to see it.
- Unchanged and noticed: a table's gutter bar is clipped by the table's own scroll container (`overflow-x: auto`), as before; its
  glow is not.
- The mock vault has `docs/design/reading-width.md` (a wide table, a long code line, a Mermaid chain, a display formula and a
  1000 px image between ordinary paragraphs; each save edits the wide blocks and drops a paragraph).
- i18n: `width.comfortable`, `width.wide`, `width.full`, `menu.width`, `status.widthHint`. Removed: `menu.wide`,
  `status.normalWidth`, `status.wide`, `settings.widthNormal`, `settings.widthWide`.

## 16. Always select the opened file (added 2026-10-14)

The Explorer should show where the open document lives, however it was opened, without anyone having to ask.
- **When**: a document becomes the open one by any route: Quick open, search, a link, the feed, Follow, back and forward, the
  restored session, the tree itself. The Explorer opens the folders above it, selects its row and scrolls it into view.
- **How it moves**: the least it can. Nothing scrolls when the row is already visible; otherwise the list scrolls by the shortest
  way (no smooth animation) and only the Explorer's own list moves. Keyboard focus stays where the person is: the tree's cursor
  moves to the file, but focus does not jump into the tree.
- **On by default**, with a checkbox "Always select the opened file" in the Explorer's `[:]` menu, next to "Reveal open doc". Turning
  it off stops the automatic reveal only; "Reveal open doc" and the breadcrumb folders still work. The choice is the session
  field `autoReveal` (per project, like the width), and a session without it means on.
- **Collapsed left panel**: nothing visible happens, but the folders are open and the row is selected, so opening the panel (or
  switching back to the Explorer from Search or Tags) shows the file at once.
- **Explorer filter**: a file the filter hides is already kept in the tree, dimmed, while it is open (section 13). It is
  revealed and selected like any other file.
- **Worktrees**: a worktree file is revealed under its worktree root, in the Worktrees section, and the section is expanded if it
  was collapsed (the project's own section is expanded for a project file).
- **Not triggered by**: a jump inside the document that is already open (an anchor link, a search hit in it), Simple mode (no
  Explorer), a failed open.
- i18n: `explorer.autoReveal`.

### Implementation notes: always select the opened file (2026-10-14, `feature/reading-width`)
- One choke point: `docs.open()` asks the Explorer to reveal on every successful open (the logic that decides is `reveal.ts`:
  `planReveal` lists the folders to open, outermost first and without the ones already open, and names the section;
  `shouldAutoReveal` weighs the setting, Simple mode and in-document jumps). Back and forward, which call `docs.open()` directly, are
  covered; before, only `app.openDoc()` revealed, so back and forward did not.
- A request that opens the file that is already open (Ctrl+P on it, a tree click) still reveals, so the tree comes back to it
  after being collapsed or scrolled away.
- `Tree.svelte` applies the reveal: it moves the tree cursor and scrolls the list with `nearestScrollTop` instead of
  `scrollIntoView` (which could also scroll the collapsed panel sideways). It waits while another sidebar view covers the Explorer
  (those rows have no layout) and applies each request once.
- `vault.revealPath()` also expands the Explorer section that holds the file, so "Reveal in tree" works from a collapsed section too.

## 17. File operations in the Explorer, with link updating (added 2026-10-14)

Like a JetBrains IDE: the Explorer can create, rename, move and delete files and folders, and keep links working.
- **Operations**: New file / New folder (Ctrl+N, §3), Rename (F2, inline), Move (drag and drop inside the tree, with a
  drop-target highlight and auto-expand on hover), Delete (Del; to the OS recycle bin, with a confirm naming the count).
  Multi-select (Ctrl/Shift+click) for move and delete. Same rules for images and other files.
- **Link updating** on rename/move: rewrite (a) links in other Markdown files that point to the moved paths, and (b) relative
  links and images inside the moved Markdown files. Anchors (`#section`) and the link's text are kept; only the target span
  of each link is rewritten (by sourcepos), every other byte stays as is.
- **Preview first**: "Update 7 links in 4 files?" with the list of changes; [Apply] [Move without updating] [Cancel].
  Setting "Update links when moving files: Ask | Always | Never" (default Ask).
- **Undo**: Ctrl+Z in the Explorer (and a toast "Moved 2 files, updated 7 links [Undo]") reverts the whole operation:
  the move and every rewrite, as long as those files did not change since.
- **Safety**: a file changed on disk between preview and apply (e.g. an agent writing it) is skipped and reported; a file
  open with unsaved edits gets the rewrite applied to its buffer, not the disk. Moves outside the project are refused.
  The live feed shows the operation as one grouped row ("Moved 2 files, 7 links updated"), not a burst.
