# v0.5 design: Notes

Open TrailMark, type, close: nothing is lost. **Notes** is a place for writing that does not belong to a project yet:
- a prompt drafted for an agent and then copied into its chat;
- a quick scrap during a meeting;
- a sticky note kept for months (server addresses, a weekly checklist);
- a loose `.md` file someone sent.

There is no name to choose, no folder to pick and no "Save changes?" prompt. Notes are written with TrailMark's own editor
and viewer.

**Principles**
- **Plain files in a folder you can see.** Every note is an ordinary `.md` file. Backing up the folder backs up everything.
- **Nothing is lost.** Every keystroke reaches the disk within seconds. Earlier versions are kept, and a deleted note goes to
  the system trash. The only automatic delete is a note that was never written in.
- **Someone else's file is never overwritten behind their back.** A loose file is written only when you save it.
- **Private by default.** Agents see no note unless you share that one note.

## 1. Where notes live

- **Folder.** The default is `Documents/TrailMark Notes/`. On Linux without an XDG Documents folder it is
  `~/TrailMark Notes/`. Settings → Notes can change it, and has an **Open notes folder** button. A synced folder (OneDrive,
  Dropbox, iCloud Drive) works.
- **Not in the app's data folder.** That folder is removed by the uninstaller's "delete app data" option and by Store
  uninstalls, which would take months of notes with it.
- **A missing folder.** If the configured folder is missing (a disconnected drive, a renamed folder), TrailMark does not
  create an empty one quietly. It says "Notes folder not found: {path}" and offers **Locate...** and **Create it**.
- **One note per file.** A new note is named after the moment it was created, for example `2026-10-15 1432.md`, plus
  `-2`, `-3` on a collision. The name never changes by itself.
  - The title shown in the list is the note's first line, with the Markdown marks removed.
  - **Rename** gives a note a real file name.
  - Files you add to the folder yourself are notes too.
- **TrailMark's own data** sits next to the notes in `.trailmark/`, which you can delete at any time and TrailMark rebuilds
  from the files:
  - `notes.json` keeps the order, pins, which notes are open, the caret, the scroll position, the mode, the "copied" marks,
    the sharing flags and the list of loose files;
  - `history/` keeps earlier versions;
  - `pending/` keeps unsaved edits to loose files.

  Nothing is ever added inside a note's text.

## 2. The Notes window

Notes is **one separate window**, and there is only ever one. It does not replace a project, so you never lose your place.

```
+---+----------------------------+-------------------------------------------------------------+
|[N]| NOTES               [+][:] | Ask the agent to add t...    Read|[Visual]|Source [Copy][:] |
|[S]| [ Filter notes...        ] |-------------------------------------------------------------|
|   | PINNED                     |                                                             |
|   | * Server IPs and ports     |  Ask the agent to add tests for the checkout storm.         |
|   |   api 10.0.0.4, db 10...   |                                                             |
|   | * Weekly checklist         |  Constraints:                                               |
|   |   [ ] backups  [ ] ...     |  - keep the block glow                                      |
|   | TODAY                      |  - do not touch the public API of `src/watcher.rs`          |
|   |>Ask the agent to add t...  |                                                             |
|   | Refactor the watcher  v 1h |                                                             |
|   | YESTERDAY                  |                                                             |
|   | Release notes for 0.4   1d |                                                             |
|   | FILES                      |                                                             |
|   | proposal.md    ~\Downloads |                                                             |
|   | old-plan.md  ! not found   |                                                             |
+---+----------------------------+-------------------------------------------------------------+
| Notes   Saved   214 words                                                            100%    |
+----------------------------------------------------------------------------------------------+
```

- **Each row** shows the title (the first line), the next line as a snippet, the time since the last edit, and `v` if the note
  was copied since it was last edited. A FILES row shows the file name and its folder. An empty note shows "Untitled note".
- **Order.**
  - **Pinned** notes come first, in the order you choose (drag, or `Alt+Up` / `Alt+Down` on a row). These are the sticky notes:
    `Ctrl+1` to `Ctrl+9` jump to them, and they are never part of a bulk delete.
  - Then the other notes by last edit: Today, Yesterday, This week, This month, Older.
  - Then **Files** (loose files, §5) by last opened.
  - A note moves up the list when you leave it, not while you type.
- **Finding a note.** Type in the filter box to filter by title and text. `Ctrl+P`, `Ctrl+T` and `Ctrl+Shift+F` search the
  notes as they search a project, but the Notes window's search covers notes only.
- **Off in the Notes window:** git badges, unread markers, "since last visit" and the agent connection. `Ctrl+B` hides the list.
- **The header** has the title, the Read | Visual | Source switch, **Copy**, and a menu with Pin, Rename, Move to project...,
  Share with agents, Show earlier versions, Delete and Open notes folder.

## 3. Getting there

- **The welcome screen** keeps recent projects and adds a **Notes** column: the pinned notes, the three latest notes, and
  **New note** (`Ctrl+Shift+N`). One keystroke takes you from launch to typing.
- **Settings → Notes → On start: Welcome screen | Notes** for anyone who wants TrailMark to open straight into Notes, the way
  Notepad++ does. The default is the welcome screen.
- **From any window,** including a project:
  - `Ctrl+Shift+N` brings the Notes window forward with a new note ready to type in.
  - `Ctrl+Shift+D` brings it forward as it was.
  - The project window keeps its document, scroll and unsaved edits.
  - A Notes icon in the activity bar and the commands **New note** and **Show notes** do the same.
- **One window, many launchers.** The Notes window listens on a local socket that only the same user can reach (the same
  kind as the agent connection). Any other TrailMark window or launch asks it to come forward, and starts it if it is not
  running.
- **Opening a loose file.** "Open with TrailMark" on a `.md` file that is not in a project window opens it in the Notes
  window and adds it to **Files** (§5). This replaces today's single-file window. A file inside a project that is open in a
  window still goes to that window.

## 4. Writing a note

1. `Ctrl+Shift+N`. A new "Untitled note" is selected at the top of Today, and the **Visual** editor has the caret, with the
   placeholder "Start typing...".
2. Nothing is written until the first character that is not blank. Then the file is created.
3. **Autosave** (Notes only; projects keep explicit saving):
   - TrailMark saves 750 ms after you stop typing, and at least every 3 s while you keep typing.
   - It also saves at once when the window loses focus, when you switch notes, when you close the window, and before an
     update restarts the app.
   - The status bar says "Saved". "Saving..." appears only if a save takes longer than a second.
4. **Closing never asks anything.** Pending saves are flushed first. When you reopen, you are back on the note you left, in
   the same mode, at the same place.
5. **The mode** is remembered for each note. A new note starts in Visual; Source is one click away.
6. **Copy** (`Ctrl+Shift+C`, or the header button) copies the whole note as Markdown text, the text of the file exactly. It
   never copies rendered HTML, so it pastes cleanly into an agent's chat.
   - A toast says "Copied 1,240 characters", with **Delete note** for a note that is not pinned.
   - The row gets the `v` mark, and editing the note clears it.
   - The list menu has **Delete copied notes (6)**, with Undo; it never deletes a pinned note.
   - In a project, the same key copies the open document.
7. **An empty note** (only blank characters, never written in) is removed when you leave it. This is the only automatic
   delete, and a pinned note is never removed.
8. **Move to project...** (`Ctrl+Shift+S`) opens the Save dialog in the most recent project, with a name made from the title.
   The note is written there and removed from Notes, and the row moves to Files. A toast offers **Open in project** and
   **Undo**.

## 5. Loose files

A loose file is any file you open that is not in a project window: from the file manager, from `Ctrl+Shift+O`, or by
dropping it. It stays in **Files** until you remove it from the list. Removing it never deletes the file.

- **It opens in Read mode.** `E` edits it.
- **TrailMark never writes it on its own.** Only `Ctrl+S` writes the file, through the same guarded save as in a project.
- **Unsaved edits are not lost.** They are kept in `pending/` together with the version they started from. Closing the window
  does not ask, and the next time the file opens with its edits and the "unsaved" mark.
- **Change detection.** TrailMark watches every listed file, and checks it again when its window gets the focus. When a file
  changed on disk, what you see is not replaced. A bar says "This file changed on disk." with **Reload** and **Keep mine**.
  This applies whether or not you have unsaved edits.
  - **Reload** loads the version on disk. Your unsaved edits are kept as a note, "{name} (my edits)", so nothing is lost.
  - **Keep mine** keeps what you see. The next `Ctrl+S` writes it over the changed file, after a second question.
  - The "Reload automatically when there are no unsaved edits" setting is off by default.
- **A missing file** (deleted, moved, or a removed drive) stays in the list, dimmed and marked "not found", with **Locate...**
  and **Remove**. A rename in the same folder is followed. If the file was open with unsaved edits, its text is kept, with
  **Save as note** and **Save it again**.
- **`.txt` files** open as plain text and are edited in Source; Visual says "Visual editing is for Markdown files". Files
  that are not UTF-8 open read-only and say so. Binary files are not added to the list.
- **Size of the list.** The 50 most recent loose files are kept, and pinned ones always.
- **Security.** A loose file is a scope of its own: only that file, plus the images next to it. The window refers to it by an
  opaque id and never sends a free path, so the rule "every path is checked against a root" still holds. Loose files are not
  indexed and never reach an agent.

## 6. Nothing is lost

- **The disk.** Notes are written through the guarded atomic save:
  - write to a temporary file;
  - flush it to the disk;
  - rename it over the note;
  - then flush the folder (Unix) or use a write-through rename (Windows).

  A power cut costs at most the last few seconds of typing.
- **A crash during a save** leaves a temporary file. When Notes opens, a temporary file that is newer than its note, from a
  process that is no longer running, is kept as "{title} (recovered)", and TrailMark says so. Temporary files in the Notes
  folder are never deleted automatically.
- **Two TrailMark windows on the same notes.**
  - The Notes window holds a lock on the folder. A second one (another install, a dev build) opens read-only, with a banner.
  - If a note changed on disk since it was opened (another computer through a synced folder, another editor), autosave does
    not overwrite it. The text you see is kept as "{title} (conflict {time})".
  - When there are no unsaved edits, the change is simply loaded.
- **History.**
  - A copy of a note is taken at the first save after you open it, then at most every 10 minutes while you edit.
  - Copies are kept for 30 days, and never fewer than the last 20 per note.
  - **Show earlier versions** lists them and restores one. The note's current text becomes a version too, so a restore can be
    undone.
- **Delete** sends a note to the system trash, with **Undo** in the toast. A pinned note asks first.

## 7. Sharing a note with agents

Notes are private: the agent connection is never on in the Notes window. A note can be shared on purpose:

- **Share with agents** (in the note's menu) marks that one note. A small mark shows it in the list and in the header.
- **What an agent can do.** An agent connected to a project whose connection is on can:
  - list the shared notes with `list_notes`, which returns the title, the time and the size;
  - read one with `read_note`.

  It cannot see notes that are not shared, cannot list the folder, and cannot change a note.
- **Turning it off.** **Stop sharing** turns it off at once. The Agent popover of the project lists "Read the note {title}"
  like any other request.

## 8. Build order

1. **Core.**
   - The Notes folder setting and checks.
   - A Notes kind of workspace: a root with no git, no unread markers and no agent connection.
   - Creating and naming notes.
   - `notes.json`, rebuilt from the files when it is missing.
   - Autosave, including the folder flush and the write-through rename on Windows.
   - The lock, recovery of temporary files, and conflict copies.
   - History.
2. **The Notes window.**
   - The list, pins, filter, copy and the copied marks, delete with Undo, the empty-note rule.
   - The welcome screen column.
   - `Ctrl+Shift+N` and `Ctrl+Shift+D` from any window, through the local socket.
   - The On start setting.
3. **Loose files.** The list, scopes of their own, watching, the "changed on disk" bar, `pending/` edits, not found, `.txt`.
   The loose-file list replaces the single-file window.
4. **Move to project, and sharing with agents** (`list_notes`, `read_note`).
5. **Release.** i18n in all four languages, README, site, CHANGELOG, then a review and a test in the real app.

## 9. Tests (none depends on timing)

- **Rust.**
  - The autosave timer as a state machine driven with explicit instants.
  - Naming collisions.
  - A missing or broken `notes.json`.
  - Recovering a temporary file placed by hand.
  - A conflict copy, using the hook that lets another writer in during a save.
  - The lock (a second process is read-only), on Windows and Unix.
  - The `pending/` round trip, including a base that changed.
  - Pruning history with the date passed in.
  - The folder fallback.
  - Agents never see a note that is not shared, and `find_project` refuses the Notes folder.
- **vitest.**
  - The autosave store with fake timers: a save after the pause, a flush on blur and on close, never a prompt.
  - The parts that are off in Notes.
  - The order of the list.
  - Copy gives exactly the text of the file.
- **In the real app,** with a sandbox identifier and a Notes folder used only for tests:
  - type, wait for "Saved", end the process, start again: the text is there;
  - change a loose file from outside: the bar appears and the text is not replaced;
  - a second process opens read-only.

## 10. Open questions

1. **Sharing.** A shared note is readable by an agent of any project whose connection is on, not of one project only. This
   design assumes any project, which is simpler and matches "I shared this note".
2. **`Ctrl+Shift+C`** in a project copies the whole document. It must be checked that the web view does not use the key for
   itself in release builds, and the same for `Ctrl+Shift+N` and `Ctrl+Tab`.

## 11. As built (build order steps 1 and 2)

Loose files (§5), **Move to project...**, **Share with agents** (§7) and `Ctrl+Shift+S` are not built yet. The rest of §1 to §4 and
§6 is, with these differences and details.

**Folder and files**
- The list is flat: the `.md` and `.markdown` files directly in the notes folder. Subfolders and files whose name starts with a
  dot are not listed. A new note is named `2026-10-15 1432.md`, then `2026-10-15 1432-2.md`, `-3` on a collision.
- A new note has a name but no file until its first character that is not blank. The first save of it is created with
  `create_new`, and if the name was taken meanwhile the note takes the next free one. A note that has no file yet cannot be
  pinned or renamed.
- `notes.json` keeps the order, pins, open note, per-note view (mode, caret line, top line), the "copied" marks and a title cache.
  The caret and scroll position are source lines, not offsets or pixels. A "copied" mark is the size and modification time the
  file had when it was copied, so any later write clears it, whoever made it. The sharing flags and the loose-file list come with
  those features.
- Debug builds default the folder to `<app data>/notes`, and the `TRAILMARK_TEST_NOTES_DIR` variable points them elsewhere. A debug
  build ignores a chosen folder that is the real default one, so development never touches real notes. Release builds use
  Documents (or `~/TrailMark Notes`) and ignore the variable.
- The Notes window keeps its session, theme and zoom in the app's data folder, not in the notes folder, so `.trailmark/` there
  holds only `notes.json`, `history/` and `notes.lock`.

**Writing and saving**
- The autosave timing (750 ms after the last key, at least every 3 s) lives in the UI, where the keystrokes are, as a small state
  machine driven by explicit instants (`autosave.ts`). The Rust side owns the history cadence and pruning, which take the instant
  and the date as arguments.
- Autosave goes through the guarded save with the hash of the text the editor loaded. A note that changed on disk while it had
  unsaved text is not overwritten: the text is written as `{title} (conflict 2026-10-15 1432)`, the editor loads the version on
  disk, and a toast says so. A clean editor just reloads. There is no conflict bar in the Notes window.
- Closing the window flushes the pending save first and never asks. A note that cannot be saved (a full disk, a read-only folder)
  keeps the window open once, so the bar that says why, with **Copy all**, is seen; closing again closes.
- Versions are named by the time of the text they hold, which is the text being replaced. One is taken at the first save after the
  note was opened, then at most every 10 minutes. Versions are kept 30 days and never fewer than the 20 newest. A restore saves
  the current text as a version first.
- Delete sends the file to the system trash. Undo recreates it from the bytes TrailMark keeps in memory (the last 8 deletions, up
  to 20 MB, and not notes over 5 MB), because the system trash has no portable "put back". The trash keeps its own copy.
- Recovered temporary files are named `{title} (recovered)`. A temporary file is only taken when its writer process is gone and it
  is newer than the note. Temporary files in the notes folder are never deleted.

**The window**
- The Notes window is the same program started with `--notes` (or with no argument when **On start** is Notes). One local socket
  per app data folder asks it to come forward, so a development build never reaches the installed one. Any other window starts it
  when it is not running.
- The groups are calendar days: Today, Yesterday, This week (two to six days ago), This month (the same calendar month), Older.
- The filter box matches titles and first lines in the list at once, and asks the search index for the text. Tags are not shown
  in Notes.
- `Ctrl+Tab` and `Ctrl+Shift+Tab` step through the list in the order it is shown; `Ctrl+1` to `Ctrl+9` open the pinned notes.
- **Delete copied notes** keeps the pinned ones and, like any delete, gives a toast with Undo.

**Open questions (§10) not settled by code.** Whether the web view of a release build keeps `Ctrl+Shift+N`, `Ctrl+Shift+D`,
`Ctrl+Shift+C` and `Ctrl+Tab` for itself needs a check in an installed build; the app handles them on `keydown` and prevents the
default, as it does for `Ctrl+N` and `Ctrl+T`.
