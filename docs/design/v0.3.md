# v0.3 design: Search everywhere, unread markers, code references, Open with on macOS and Linux

Builds on `v0.2.md`. Sections 4 (unread) and 5 (code references) of that file are the base design; this file records what
changes and the decisions needed to build them. Every new string goes through `src/lib/i18n/` in en, pt-BR, es and de.

## 1. Search everywhere (`Ctrl+T`)

One box that finds files, sections, tags and commands. It grows out of Quick open (same overlay, same row styles), so
there is one search surface to learn, not three.

```
┌──────────────────────────────────────────────────────────────┐
│ 🔍 auth token                                                │
│  All   Files   Sections   Tags   Commands          Tab ⇥     │
├──────────────────────────────────────────────────────────────┤
│ FILES                                          Show all (7) │
│  ▸ auth-flow.md          docs/design                         │
│  ▸ token-refresh.md      docs/plans                          │
│ SECTIONS                                      Show all (23) │
│  § Refreshing the token  auth-flow.md › Login                │
│    …the access <mark>token</mark> expires after 15 minutes…  │
│ TAGS                                                         │
│  #auth  12 files                                             │
│ COMMANDS                                                     │
│  ⌘ Toggle outline                               Ctrl+Alt+O   │
└──────────────────────────────────────────────────────────────┘
```

- **Scopes**: All, Files, Sections, Tags, Commands, as a tab strip under the box. `Tab` / `Shift+Tab` move between scopes
  (unless a tag suggestion is open, where `Tab` completes the tag as today). Clicking a scope or a group's "Show all (N)"
  switches to it. The scope is remembered for the session.
- **Entry points**: `Ctrl+T` opens All. `Ctrl+P` keeps its meaning and opens the Files scope (it *is* Quick open now).
  `Ctrl+Shift+P` opens Commands. Typing `>` as the first character switches to Commands, `#` to Sections (the prefix is
  removed from the query). `Ctrl+K` stays unbound outside the editor.
- **Empty query**: All and Files list the recent files exactly as Quick open does today (changed, then opened). Sections
  shows the outline of the open document. Tags lists every tag by count. Commands lists every available command.
- **All**: groups in a fixed order: Files (5), Sections (5), Tags (3), Commands (3). A group with no results is left out.
  Fixed order (not mixed by score) keeps the keyboard path predictable: the first row is the best file.
- **Files**: today's Quick open logic unchanged (`tag:` chips, description matches, the "+N hidden files match" row).
- **Sections**: the existing BM25 section search (`search` command), debounced ~80 ms, limit 50. Row: the section's own
  heading, then file name and the heading path in muted text, then a one-line snippet. Enter opens the file at the
  section (the same way the Search panel does). Files the Explorer filter hides are left out, as in Quick open.
  This is the seam for v0.5: semantic results arrive through the `SearchProvider` in Rust; the UI does not change.
- **Tags**: tags whose name matches (fuzzy), by file count. Enter puts the tag as a `tag:` chip in the box and switches to
  Files, so the next keystroke picks a file with that tag.
- **Commands**: a registry (`src/lib/commands.ts`) of the app's actions: every `ShortcutAction` plus actions without a
  shortcut (Initialize TrailMark, Check for updates, Mark all read, Show only unread, and so on). Each entry has an id, an
  i18n label key, an optional shortcut (shown on the right, formatted per platform), and an `available()` check (Save only
  while editing, Next change only with changes). Matching uses the label in the current language and the English label,
  so muscle memory survives a language switch. Enter closes the box and runs it through `app.run`.
- **Model**: a pure `searchEverywhereModel.ts` (scopes, prefixes, grouping, limits, keyboard order) with vitest tests;
  `QuickOpen.svelte` becomes the Search everywhere overlay (rename allowed).

### Implementation notes: Search everywhere (`feature/search-everywhere`)

Quick open became the Search everywhere overlay (`SearchEverywhere.svelte`): same box, same rows, plus the scope strip. The
logic is in two pure modules with tests: `searchEverywhereModel.ts` (scopes, prefixes, the rows of each scope, the grouping
and limits of All, the keyboard order) and `commands.ts` (the registry and the matching). The overlay only gathers the
state of the app, hands it to the model and draws the answer.

What was built, as designed: the five scopes with Tab / Shift+Tab (Tab still completes an open tag suggestion), `Ctrl+T`,
`Ctrl+P` (Files, as before) and `Ctrl+Shift+P` (Commands), the `>` and `#` prefixes, "Show all (N)" on the group headers,
and the empty states (recent files in All and Files, the outline of the open document in Sections, every tag by count,
every available command). Sections use the existing section search, asked after an 80 ms pause, and open at the section the
way the Search panel does. A tag picked in Tags becomes a `tag:` chip and the box moves to Files. Shortcuts are written
for the platform: `⇧⌘P` on macOS, and the key names of the language elsewhere (`Strg+Umschalt+P`).

Decisions the design left open:

- **Which scope `Ctrl+T` opens.** The design says both "opens All" and "the scope is remembered for the session". `Ctrl+T`
  opens All the first time and then the scope last picked with Tab or a click on the strip; `Ctrl+P` and `Ctrl+Shift+P`
  always open Files and Commands, and a prefix does not change what is remembered. Pressing a shortcut while the box is
  open switches it to that scope.
- **The box opening itself is not a command.** Every other action of the keyboard map is listed. Besides those, the
  commands without a key are: Initialize TrailMark, Check for updates (it opens the settings, where the answer shows), New
  folder, Collapse all folders, Reveal open doc in Explorer, Show changes since last visit / since last commit, and Open
  containing folder (Simple mode). A test fails when a keyboard action has no entry, and checks that the key shown next to
  a command is the one that runs it. Adding a command is one entry in `COMMANDS`, a `cmd.<id>` label in each language and,
  for an action with no key, a case in `app.run`.
- **Matching commands.** Every typed word must be in the label, in any order, in the current language or in English; when
  the English label is the one that matched, it is shown beside the translated one. The typed letters in order are tried
  only when no label has the words, so `tog` lists the Toggle commands and not every label that has a t, an o and a g.
- **Simple mode** (one file open, no folder): only `Ctrl+Shift+P` opens the box, with the Commands scope alone. `Ctrl+T`
  and `Ctrl+P` still do nothing there, as `Ctrl+P` did.
- **All keeps to files, sections, tags and commands.** The "+N hidden files match" row belongs to the Files scope only. With
  only `tag:` filters and no words, All lists just the files that have the tags.
- The hint for Tab is in the footer of the box, next to the other keys, instead of on the right of the strip.

## 2. Unread markers

Base design: `v0.2.md` §4 (read = focused window + scrolled, or visible 3 s; dot in tree, Quick open, Search, Tags view,
Since last visit; folder semibold + dot with "N unread"; Mark all read, Show only unread, Mark folder read, Mark as unread,
`Alt+U` next unread). Decisions for the build:

- **The state lives in Rust**, so the v0.4 agent bridge can read it: per project, `read.json` next to the other local
  state (`.trailmark/local/` or AppData, as the session store decides), `{ path: xxh3 hash of the content }`. The UI
  receives the unread set and an event when it changes; it never computes hashes.
- **Baseline**: when a project has no read state yet (first visit, or the first visit after updating), every existing
  file counts as read. Files created after that start unread. A file removed is dropped from the state.
- **What is tracked**: Markdown documents only (not images or other files).
- **Changes on disk**: the watcher already reports changed files; Rust recomputes the hash for those and emits the new
  unread set. A file reverted to the content last read becomes read again (the hash matches).
- **Own edits**: saving from the editor marks the file read.
- **Worktrees**: files of linked worktrees are tracked like any other path.
- **Commands** (also in Search everywhere): Next unread (`Alt+U`), Mark all read, Show only unread (Explorer filter),
  Mark folder read (folder context menu), Mark as unread (document menu).
- `Alt+U` order: the change feed (newest first), then tree order. With nothing left: toast "All caught up."

## 3. Code references

Base design: `v0.2.md` §5. Decisions for the build:

- **Detection** happens in the rendered DOM (the same enhancement pass that handles links), never in code blocks or
  existing links:
  - inline code that is a path with an optional line: `src/main.rs`, `src/main.rs:42`, `main.rs:42:7`,
    `lib.rs#L10`, `lib.rs#L10-L20`, `lib.rs:10-20`;
  - plain text only when it has a line suffix (`src/main.rs:42`), to avoid false links in prose.
  - A reference becomes a link only when it resolves to an existing file: relative to the project root, then to the
    document's folder, then a unique file-name match in the project. Several candidates: clicking shows a small menu of
    them. No match: plain text.
- **Resolution and parsing** are pure TypeScript (`codeRefs.ts`) with tests; the UI already knows every file.
- **Click**: a Markdown file opens in TrailMark at the line (section tint). Any other file runs the editor command.
  `Ctrl`+click on a Markdown reference also uses the external editor.
- **Editor command** (Settings, "External editor"): a preset list plus Custom.

  | Preset | Template |
  |---|---|
  | System default app (default) | (opens the file, line ignored) |
  | VS Code | `code -g {path}:{line}:{col}` |
  | Cursor | `cursor -g {path}:{line}:{col}` |
  | Zed | `zed {path}:{line}:{col}` |
  | Sublime Text | `subl {path}:{line}:{col}` |
  | JetBrains IDEs | `idea --line {line} {path}` |
  | Custom | free text |

  The template is split into arguments (quotes respected) before substitution, so `{path}` is always one argument,
  whatever it contains. It is run without a shell. On Windows the program is looked up on `PATH` with `PATHEXT`, so
  `code` finds `code.cmd`. A failure shows the toast of §5 with a Settings button.
- The same command powers "Open in external editor" (`Ctrl+Shift+E`), with the line of the block at the top of the view.
- Context menu on a reference: Open, Open in external editor, Copy path, Copy reference.

## 4. "Open with TrailMark" on macOS and Linux

Windows keeps its own opt-in registration (`v0.2.md` §14); the platform-specific config files keep Tauri's
`fileAssociations` out of the Windows installers.

- **macOS** (`tauri.macos.conf.json`): document types for `.md` / `.markdown` (role Viewer, rank Alternate, so TrailMark
  is listed in Finder's "Open With" without taking over the default) and for folders (`public.folder`), so a folder dropped
  on the Dock icon opens as a project. macOS hands files over with an Apple Event, not as an argument: the app handles
  `RunEvent::Opened`. At launch the first URL becomes the initial path; while running, a path opens in this window when
  no project is open, otherwise a new TrailMark process is started for it (one process per project, as elsewhere).
- **Linux** (`tauri.linux.conf.json`): the `.desktop` entry of the `.deb` and `.rpm` declares `MimeType=text/markdown;`,
  so file managers list TrailMark under "Open With" for Markdown files. Folders are not declared: an
  `inode/directory` entry can make an app the default folder handler on some desktops. Folders open from a terminal
  (`trailmark <folder>`). The AppImage has no desktop integration of its own.
- **Verification**: CI builds the bundles on both platforms; a test reads the generated `Info.plist` / `.desktop` where the
  build produces them. Manual checks (Finder "Open With", Dock drop, Nautilus "Open With") are listed in the release
  notes for testers.
