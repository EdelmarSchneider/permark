# v0.3 design: Search everywhere, unread markers, code references, Open with on macOS and Linux

Builds on `v0.2.md`. Sections 4 (unread) and 5 (code references) of that file are the base design; this file records what
changes and the decisions needed to build them. Every new string goes through `src/lib/i18n/` in en, pt-BR, es and de.

## 1. Search everywhere (`Ctrl+T`)

One box that finds files, sections, tags and commands. It grows out of Quick open (same overlay, same row styles), so
there is one search surface to learn, not three.

```
┌──────────────────────────────────────────────────────────────┐
│ 🔍 auth token                                                │
│  All   Files   Sections   Tags   Commands          Tab ⇥     │
├──────────────────────────────────────────────────────────────┤
│ FILES                                          Show all (7) │
│  ▸ auth-flow.md          docs/design                         │
│  ▸ token-refresh.md      docs/plans                          │
│ SECTIONS                                      Show all (23) │
│  § Refreshing the token  auth-flow.md › Login                │
│    …the access <mark>token</mark> expires after 15 minutes…  │
│ TAGS                                                         │
│  #auth  12 files                                             │
│ COMMANDS                                                     │
│  ⌘ Toggle outline                               Ctrl+Alt+O   │
└──────────────────────────────────────────────────────────────┘
```

- **Scopes**: All, Files, Sections, Tags, Commands, as a tab strip under the box. `Tab` / `Shift+Tab` move between scopes
  (unless a tag suggestion is open, where `Tab` completes the tag as today). Clicking a scope or a group's "Show all (N)"
  switches to it. The scope is remembered for the session.
- **Entry points**: `Ctrl+T` opens All. `Ctrl+P` keeps its meaning and opens the Files scope (it *is* Quick open now).
  `Ctrl+Shift+P` opens Commands. Typing `>` as the first character switches to Commands, `#` to Sections (the prefix is
  removed from the query). `Ctrl+K` stays unbound outside the editor.
- **Empty query**: All and Files list the recent files exactly as Quick open does today (changed, then opened). Sections
  shows the outline of the open document. Tags lists every tag by count. Commands lists every available command.
- **All**: groups in a fixed order: Files (5), Sections (5), Tags (3), Commands (3). A group with no results is left out.
  Fixed order (not mixed by score) keeps the keyboard path predictable: the first row is the best file.
- **Files**: today's Quick open logic (`tag:` chips, description matches, the "+N hidden files match" row). A query of
  several words that does not match as typed finds the paths that have each word, in any order (`auth token` finds
  `auth/token-refresh.md`); a query of one word is ranked as before.
- **Sections**: the existing BM25 section search (`search` command), debounced ~80 ms, limit 50. Row: the section's own
  heading, then file name and the heading path in muted text, then a one-line snippet. Enter opens the file at the
  section (the same way the Search panel does). Files the Explorer filter hides are left out, as in Quick open.
  This is the seam for v0.5: semantic results arrive through the `SearchProvider` in Rust; the UI does not change.
- **Tags**: tags whose name matches (fuzzy), by file count. Enter puts the tag as a `tag:` chip in the box and switches to
  Files, so the next keystroke picks a file with that tag.
- **Commands**: a registry (`src/lib/commands.ts`) of the app's actions: every `ShortcutAction` plus actions without a
  shortcut (Initialize TrailMark, Check for updates, Mark all read, Show only unread, and so on). Each entry has an id, an
  i18n label key, an optional shortcut (shown on the right, formatted per platform), and an `available()` check (Save only
  while editing, Next change only with changes). Matching uses the label in the current language and the English label,
  so muscle memory survives a language switch. Enter closes the box and runs it through `app.run`.
- **Model**: a pure `searchEverywhereModel.ts` (scopes, prefixes, grouping, limits, keyboard order) with vitest tests;
  `QuickOpen.svelte` becomes the Search everywhere overlay.

### Implementation notes: Search everywhere (`feature/search-everywhere`)

Quick open became the Search everywhere overlay (`SearchEverywhere.svelte`): same box, same rows, plus the scope strip. The
logic is in two pure modules with tests: `searchEverywhereModel.ts` (scopes, prefixes, the rows of each scope, the grouping
and limits of All, the keyboard order) and `commands.ts` (the registry and the matching). The overlay only gathers the
state of the app, hands it to the model and draws the answer.

What it does: the five scopes with Tab / Shift+Tab (Tab still completes an open tag suggestion), `Ctrl+T`,
`Ctrl+P` (Files, as before) and `Ctrl+Shift+P` (Commands), the `>` and `#` prefixes, "Show all (N)" on the group headers,
and the empty states (recent files in All and Files, the outline of the open document in Sections, every tag by count,
every available command). Sections use the existing section search, asked after an 80 ms pause, and open at the section the
way the Search panel does. A tag picked in Tags becomes a `tag:` chip and the box moves to Files. Shortcuts are written
for the platform: `⇧⌘P` on macOS, and the key names of the language elsewhere (`Strg+Umschalt+P`).

Decisions:

- **Which scope `Ctrl+T` opens.** `Ctrl+T` opens All the first time, and then the scope last picked with Tab or a click on
  the strip (the scope is remembered for the session); `Ctrl+P` and `Ctrl+Shift+P` always open Files and Commands, and a
  prefix does not change what is remembered. Pressing a shortcut while the box is open switches it to that scope.
- **The box opening itself is not a command.** Every other action of the keyboard map is listed. Besides those, the
  commands without a key are: Initialize TrailMark, Check for updates (it opens the settings, where the answer shows), New
  folder, Collapse all folders, Reveal open doc in Explorer, Show changes since last visit / since last commit, and Open
  containing folder (Simple mode). A test fails when a keyboard action has no entry, and checks that the key shown next to
  a command is the one that runs it. Adding a command is one entry in `COMMANDS`, a `cmd.<id>` label in each language and,
  for an action with no key, a case in `app.run`.
- **Matching commands.** Every typed word must be in the label, in any order, in the current language or in English; when
  the English label is the one that matched, it is shown beside the translated one. The typed letters in order are tried
  only when no label has the words, so `tog` lists the Toggle commands and not every label that has a t, an o and a g.
- **Simple mode** (one file open, no folder): only `Ctrl+Shift+P` opens the box, with the Commands scope alone. `Ctrl+T`
  and `Ctrl+P` still do nothing there, as `Ctrl+P` did.
- **All keeps to files, sections, tags and commands.** The "+N hidden files match" row belongs to the Files scope only. With
  only `tag:` filters and no words, All lists just the files that have the tags.
- The hint for Tab is in the footer of the box, next to the other keys, instead of on the right of the strip.

## 2. Unread markers

Base design: `v0.2.md` §4 (read = focused window + scrolled, or visible 3 s; dot in tree, Quick open, Search, Tags view,
Since last visit; folder semibold + dot with "N unread"; Mark all read, Show only unread, Mark folder read, Mark as unread,
`Alt+U` next unread). Decisions for the build:

- **The state lives in Rust**, so the v0.4 agent bridge can read it: per project, `read.json` next to the other local
  state (`.trailmark/local/` or AppData, as the session store decides), `{ path: xxh3 hash of the content }`. The UI
  receives the unread set and an event when it changes; it never computes hashes.
- **Baseline**: when a project has no read state yet (first visit, or the first visit after updating), every existing
  file counts as read. Files created after that start unread. A file removed is dropped from the state.
- **What is tracked**: Markdown documents only (not images or other files).
- **Changes on disk**: the watcher already reports changed files; Rust recomputes the hash for those and emits the new
  unread set. A file reverted to the content last read becomes read again (the hash matches).
- **Own edits**: saving from the editor marks the file read.
- **Worktrees**: files of linked worktrees are tracked like any other path. A worktree that appears after the baseline (an
  agent made it) is a first visit of its own: its existing documents start read, so it does not arrive as a flood of dots;
  what is added to a worktree the project already knows is unread.
- **Commands** (also in Search everywhere): Next unread (`Alt+U`), Mark all read, Show only unread (Explorer filter),
  Mark folder read (folder context menu), Mark as unread (document menu).
- `Alt+U` order: the change feed (newest first), then tree order. With nothing left: toast "All caught up."

### Implementation notes: unread markers (`feature/unread`)

The books are kept in Rust, in the new `unread` module (`state.rs` holds the rules and is tested without files, `mod.rs` keeps
them true). The UI never computes a hash: it asks for the unread set (`get_unread`), hears about changes (`unread-changed`, whose
payload is the whole sorted list, so there is nothing to fetch after it) and sends `mark_read`, `mark_unread`, `mark_all_read` and
`mark_folder_read`. Search everywhere lists each of them as a command.

**What the agent bridge (v0.4) can read.** `read.json` sits next to the other local state: `.trailmark/local/read.json` in an
initialized project, else `projects/<hash of the project path>/read.json` in the app's data folder. Initializing the project copies the
local state files (session, last visit, window and `read.json`) into `.trailmark/local/`, as it always did, and the unread markers write
their current state there from then on; the copy in the app's data folder is left behind and is used again only if `.trailmark/` is
deleted. It is a JSON object from a document's path in the project (`/`-separated, `@wt/<name>/...` for a
linked worktree) to the xxh3 64-bit hash of the document's bytes when it was last read, as 16 lowercase hex digits:

```json
{ "docs/spec.md": "a1b2c3d4e5f60718" }
```

A document is unread when it is not listed or when its hash today differs; a document that is not Markdown is never listed. The
file is written atomically and a moment after the last change, and the app is the only writer. A project with no `read.json` has no
baseline yet; the file is written, even when empty, once the first look at the folder is done.

**The reading rule** lives in a pure module with an injectable clock (`readTracker.ts`). A document is read when it is on show in
the reading view of a window that has the focus, and the reader scrolled it by hand or it stayed three seconds. A live change that
arrives in a focused window after the document was read stays read; one that arrives while the window has no focus (or while the
document is in the editor) makes it unread until the rule passes again. A scroll that the app made (a restored position) does not
count. Saving from the editor, and creating a file with New file, mark the document read on the spot, from the hash the write
returned.

What is shown: a 6px accent dot in the tree, in the Search everywhere file rows, in the Search panel's file groups, in
the Tags view's file list and in the Since last visit rows; a folder with something unread inside is semibold with a dot and the
tooltip "N unread". The Explorer `[:]` menu has "Mark all read" and "Show only unread" (with a footer that says so and a "Show all"
button, and "All caught up." when nothing is left), a folder's context menu has "Mark folder read", the document's `[:]` menu has
"Mark as unread", and `Alt+U` opens the next unread document.

Decisions:

- **Baseline and the first look.** The folder is read once on a background thread when it opens (the second and later looks only
  hash what changed in size or time). Until it is done nothing is unread, so the tree never shows a flood. A project that is closed
  before the first look finished leaves no `read.json` and gets its baseline the next time. A `read.json` that cannot be read is
  taken as no state at all (everything counts as read), never as "everything is new".
- **Moves and renames.** What was read stays read when the app moves or renames a file or a folder (the same place where tags
  follow), and when the watcher reports a rename it did not make. A move with "update links" rewrites other documents: those that
  were read stay read, with the hash of their new text (the file operations tell the followers the hash before and after, and an
  undo tells them back). A move that turned a dozen documents unread would be noise.
- **Deleted, then back.** A document that is removed is dropped from the state, so a file that returns (a checkout, or
  an undo of a delete) starts unread.
- **Whatever the disk says.** A change reported by the watcher is looked at on the disk: a file that is there is hashed, whatever
  the event said, and one that is not is gone. A file an agent saves by deleting and writing it in one batch keeps its state when the
  text is the same.
- **Mark as unread on the open document** holds it: it is not read again while it stays on show (otherwise the rule would read it
  again three seconds later). Leaving the document and coming back lifts the hold.
- **`Alt+U`** goes to the document after the one on show in the order of the walk (the live feed, newest first, then tree order),
  wrapping round; when the document on show is read, to the first. When the only unread document is the one on show, it says
  "All caught up." too. The walk includes unread documents the Explorer filter hides.
- **Show only unread** keeps the open document in the list even when it is read, so it does not vanish three seconds after it
  opens; when nothing is unread, "All caught up." shows under it. It is not remembered between launches.
- **The dot in the tree.** A file's dot takes the slot a folder keeps for its twisty, so names stay in one column; a folder's dot
  comes after its twisty. In the lists the dot comes before the name.
- **Commands without a menu.** "Mark folder read" in Search everywhere acts on the folder the tree cursor is in, else the folder
  of the open document (the project root counts as every folder). "Mark all read" and "Mark folder read" are offered only while
  something is unread; "Next unread" always, so that it can say "All caught up.".
- **Simple mode** (one file open) has no markers and keeps no state.
- Documents over 32 MB are not tracked. The watcher itself was not changed: the workspace hands what it reports to the unread
  thread, which hashes the files on its own thread.

Unit tests cover both sides: the rules, the thread with real files, the workspace with the live watcher, the reading rule with a
clock moved by hand, the store, the walk of `Alt+U` and the Explorer filter. A scan that runs while the app moves, makes or marks
documents leaves those changes alone: the tracker remembers what changed since the scan began and keeps those entries. Closing the
window waits at most half a second for `read.json` to be written; stopping the project writes it and cuts a scan short.

## 3. Code references

Base design: `v0.2.md` §5. Decisions for the build:

- **Detection** happens in the rendered DOM (the same enhancement pass that handles links), never in code blocks or
  existing links:
  - inline code that is a path with an optional line: `src/main.rs`, `src/main.rs:42`, `main.rs:42:7`,
    `lib.rs#L10`, `lib.rs#L10-L20`, `lib.rs:10-20`;
  - plain text only when it has a line suffix (`src/main.rs:42`), to avoid false links in prose.
  - A reference becomes a link only when it resolves to an existing file: relative to the project root, then to the
    document's folder, then a unique file-name match in the project. Several candidates: clicking shows a small menu of
    them. No match: plain text.
- **Resolution and parsing** are pure TypeScript (`codeRefs.ts`) with tests; the UI already knows every file.
- **Click**: a Markdown file opens in TrailMark at the line (section tint). Any other file runs the editor command.
  `Ctrl`+click on a Markdown reference also uses the external editor.
- **Editor command** (Settings, "External editor"): a preset list plus Custom.

  | Preset | Template |
  |---|---|
  | System default app (default) | (opens the file, line ignored) |
  | VS Code | `code -g {path}:{line}:{col}` |
  | Cursor | `cursor -g {path}:{line}:{col}` |
  | Zed | `zed {path}:{line}:{col}` |
  | Sublime Text | `subl {path}:{line}:{col}` |
  | JetBrains IDEs | `idea --line {line} {path}` |
  | Custom | free text |

  The template is split into arguments (quotes respected) before substitution, so `{path}` is always one argument,
  whatever it contains. It is run without a shell. On Windows the program is looked up on `PATH` with `PATHEXT`, so
  `code` finds `code.cmd`. On macOS and Linux the folders where editors put their command (`/opt/homebrew/bin`,
  `/usr/local/bin`, `~/.local/bin`, the JetBrains Toolbox scripts) are searched after `PATH`, because an app started from
  the Dock or a file manager gets a short `PATH`. The editor starts in the home folder, never in the project. A failure
  shows the toast of §5 with a Settings button.
- The same command powers "Open in external editor" (`Ctrl+Shift+E`), with the line of the block at the top of the view.
- Context menu on a reference: Open, Open in external editor, Copy path, Copy reference.

### Implementation notes: code references (`feature/code-refs`)
The details of the build.

**Reading a reference** (`codeRefs.ts`, pure). A reference is a path whose last segment has an extension with at least one letter (so `1.2` and
`192.168.1.1` are numbers, not files), written with `/` or `\`, optionally with a line: `:42`, `:42:7`, `:10-20`, `#L10`, `#L10C5`, `#L10-L20`. Names
may hold letters, digits and `_ . @ + ~ -`, but no space, so prose around a path ends it. In inline code the whole span must be the reference
and the line is optional; in plain text the line is required and the reference is never read from the middle of a longer token (a URL, a drive
path like `C:\x\main.rs:42`, `path=src/main.rs:3`). `@src/main.rs:42`, the way **Copy reference** writes it, is read as `src/main.rs:42`. Not
recognized, on purpose: names without an extension (`Makefile:3`), names with spaces, absolute paths (a leading `/` means the project root, so a real
absolute path simply finds no file). The last line of a range is parsed, but only the first line is used: the section tint covers the block that holds it.

**Finding the file** (`resolveCodeRef`). Project root, then the document's folder, then the end of the path among the project's files (so
`lib/util.ts` finds `src/lib/util.ts`, and a bare file name works). One hit is a link; several are listed on click, the closest to the document first;
a name that matches more than 12 files (`mod.rs`, `index.ts` in a big repository) is left as text, because a guess among that many helps nobody.
A document inside a linked worktree looks only inside that worktree, and a document in the main folder never looks into the worktrees (which hold a
copy of every file, so no name would ever be unique). The files come from the list the Explorer already has; nothing is read from disk, and the
references are looked up again when the project's files change, so a file the agent creates a minute later turns the reference into a link.

**On the page** (`dom/codeRefsDom.ts`, called from the enhancement pass). Inline code is marked in place (class `code-ref`, `role="link"`,
`tabindex="0"`, the target in `data-ref-*`); plain text is split and the reference wrapped in a span. Code blocks, links, buttons, `kbd`, math,
diagrams and removed-block markers are skipped, and everything added can be taken off again exactly (tested byte for byte). Only the reading view
turns references into links: the locked blocks of the Visual editor are drawn by the same pass, but nothing there would handle a click. They are
not `<a>` elements, so the link handling of the page (which follows `href`s) never sees them; Enter does what a click does. Simple mode has no
references: it has no project to look in.

**Opening.** A Markdown file opens in TrailMark at the line (the same `locate` request a search hit uses, so it scrolls and tints the block);
`Ctrl`+click (`Cmd` on macOS) and every other file go to the editor command. On a name that several files share, a click opens a menu of the files;
the right-click menu of a reference that names one file has Open, Open in external editor (Markdown files only; for any other file Open already is
that), Copy path and Copy reference, which keeps the line (`@src/main.rs:42`).

**The command** (`src-tauri/src/external_editor.rs`, no Tauri in it). The template is split into arguments first (whitespace separates, `"` and `'`
group, a backslash is never an escape so Windows paths are written as they are) and the placeholders `{path}` (absolute), `{line}` and `{col}` (both
from 1) are filled in after, one pass, so a path is one argument whatever it contains, even `{line}` or a quote. The program can't be a
placeholder. It is looked up on `PATH` (absolute folders only; a program with a folder in it must be absolute) and then, on macOS and Linux, in the
folders editors usually install to (`/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin` and the JetBrains Toolbox scripts; on Linux also
`/snap/bin`), because a program started from the Dock or a file manager does not get the `PATH` of a terminal. On Windows the lookup uses `PATHEXT`
limited to what can be started (`.com .exe .bat .cmd`), so `code` finds `code.cmd`. It is started directly with no shell and no console window,
with no input or output, in the home folder (the temporary folder when there is none) and never in the project; Windows is also told not to look for
programs in the working folder. The app collects its exit status in a thread. Rust refuses arguments a batch file can't take safely (a line break),
and that comes back as an error. The command parses before it is saved, so what is kept always runs. The file must be inside the open folder
(`Workspace::editor_target`); any extension will do, because it is only an argument to the program the person chose. With no command the system's default app
opens the file, for documents and images only (and plain files without an extension: one with an execute bit is refused on macOS and Linux, where
the system would run it).

**Settings.** The command lives in the app-wide settings (`settings.json` in the app's data folder, key `editorCommand`), not in the project's
session and not in `.trailmark/config.toml`: a cloned folder must never be able to choose what runs when someone clicks a reference. The presets are
the table above (the Notepad++ preset of `v0.2.md` section 7 is not offered; Custom covers it). Picking a preset fills the command; typing makes it Custom
unless the text is a preset; the field is kept 400 ms after typing stops and when Settings closes. A command the backend refuses is not kept: the field says
"Not saved: unknown placeholder {file}" and the last good command stays in force. Under it, a preview with a sample file ("Preview: code -g
F:\proj\docs\a.md:42:1", a path with spaces in quotes).

**"Open in external editor"** (`Ctrl+Shift+E`, the header menu, the Explorer menu) uses the same command. For the open document the line is the block
at the top of the view (the line of the editor, while editing); for a file of the Explorer there is none. Images and PDF files still go to the system's
application whatever the command is: a code editor shows them worse. Without a command, a code file can't be opened by the system default (it only opens
documents and images), and the message says so and offers Settings.

**Errors.** The backend reports `kind: "editor"` with a `reason` and a `subject`: `notFound`, `badArguments` and `spawn` name the program; a command that
can't be read is `missingProgram`, `unclosedQuote`, `unknownPlaceholder` (the placeholder is the subject) or `placeholderInProgram`. The UI words
all of them in four languages: "Couldn't run 'code': not found. Set the editor command in Settings." with a **Settings** button on the toast.

**Limits.** The tests start scripts of their own (a `.cmd` on Windows, a shell script on Unix) and check the arguments and the working folder
they receive; no real VS Code, Cursor, Zed, Sublime or JetBrains install is started. Absolute paths in references are not read (a follow-up could strip the project's own
folder from them). The mock vault has `docs/design/code-refs.md` and a few source files to try it in a browser, which is why the editor's round-trip
fixtures were regenerated.

## 4. "Open with TrailMark" on macOS and Linux

Windows keeps its own opt-in registration (`v0.2.md` §14); the platform-specific config files keep Tauri's
`fileAssociations` out of the Windows installers.

- **macOS** (`tauri.macos.conf.json`): document types for `.md` / `.markdown` (role Viewer, rank Alternate, so TrailMark
  is listed in Finder's "Open With" without taking over the default) and for folders (`public.folder`), so a folder dropped
  on the Dock icon opens as a project. macOS hands files over with an Apple Event, not as an argument: the app handles
  `RunEvent::Opened`. At launch the first URL becomes the initial path; while running, a path opens in this window when
  no project is open. With a project open, the project's own folder or a path inside it is shown in this window (the file
  opens; a folder only brings the window forward), because a second process on the same project would write the same
  state files; any other path starts a new TrailMark process (one process per project, as elsewhere).
- **Linux** (`tauri.linux.conf.json`): the `.desktop` entry of the `.deb` and `.rpm` declares `MimeType=text/markdown;`,
  so file managers list TrailMark under "Open With" for Markdown files. Folders are not declared: an
  `inode/directory` entry can make an app the default folder handler on some desktops. Folders open from a terminal
  (`trailmark <folder>`). The AppImage has no desktop integration of its own.
- **Verification**: CI builds the bundles on both platforms; a test reads the generated `Info.plist` / `.desktop` where the
  build produces them. Manual checks (Finder "Open With", Dock drop, Nautilus "Open With") are listed in the release
  notes for testers.

### Implementation notes: Open with on macOS and Linux (`feature/open-with-unix`)

**macOS.** `src-tauri/tauri.macos.conf.json` declares two document types with Tauri's `fileAssociations`; a merged
`Info.plist` was not needed, because `contentTypes` maps to `LSItemContentTypes` and an empty `ext` list leaves out
`CFBundleTypeExtensions`.

| Document type | Declared as | Role, rank |
| --- | --- | --- |
| Markdown | `md`, `markdown`, content type `net.daringfireball.markdown`, MIME `text/markdown` | Viewer, Alternate |
| Folder | no extensions, content type `public.folder` | Viewer, Alternate |

- Markdown's type belongs to others, so it is referred to and never exported (no `UTExportedTypeDeclarations`). Alternate
  rank is what keeps TrailMark in the "Open With" list without becoming anyone's default.
- Finder hands over what it opens as an event, so `RunEvent::Opened` goes to `commands::opened`, which asks the new
  `open_request` module what to do with each path. The module has no window system in it and is tested on every platform:

  | The app is | Project in the window | First path | Other paths |
  | --- | --- | --- | --- |
  | starting (the UI has not asked what to open) | n/a | kept as the initial path; `initial_path` returns it before the command-line argument | a new process each |
  | running | none | opens in this window (the `open-path` event; the window is brought to the front) | a new process each |
  | running | a folder is open | inside it: shown in this window (the `show-in-project` event); elsewhere: a new process | each one placed the same way |
  | running | a single file is open | a new process | a new process each |

- `show-in-project` carries the file's path in the project, and the window opens it as a document. The project's own folder and
  a folder inside it carry nothing: the window is brought to the front and nothing else changes.
- A new process is `current_exe()` with the path as its only argument, the way the command line and the Windows menu
  already start one. Anything that is not an existing local file or folder (another URL scheme, a path that is gone) is
  ignored. The window handles `open-path` with the same `openProject` as a folder dropped on it.
- Known limit: at launch the window is placed before Finder's event arrives, so a project opened this way first appears
  where the app-wide window state puts it, not where that project was last closed.

**Linux.** `src-tauri/tauri.linux.conf.json` declares `md` / `markdown` with MIME type `text/markdown`, which Tauri writes
as `MimeType=` in the `.desktop` entry. Tauri's own template writes `Exec=trailmark` with no field code, and a desktop
entry without one is started with no file, so "Open With" would have opened an empty window. The deb and rpm therefore use
`src-tauri/installer/trailmark.desktop`, the same template with `Exec=trailmark %f` and `MimeType=text/markdown;`.

- `%f` rather than `%F`: the app takes one path per process, so with several files selected the file manager starts it
  once for each, where `%F` would have opened the first and silently dropped the rest. `%U` hands over `file://` URLs,
  which the app does not read.
- No `inode/directory`: folders open with `trailmark <folder>` from a terminal.
- The AppImage has no desktop integration of its own.

**Windows** is untouched: its config and installers have no file associations, and a test says so.

**What CI verifies** (`npm run check` on Windows, Ubuntu and macOS, no bundling):
- the URL-to-path conversion and every row of the table above, including a poisoned lock and a repeated delivery;
- both platform files, read as the bundler reads them (Tauri's own `FileAssociation` and `LinuxConfig` types reject
  unknown fields and unknown role or rank names): extensions, role and rank, MIME type and content types, no
  `inode/directory`, the desktop template exists for both the deb and the rpm and ends its `Exec` line with `%f`, and it
  uses only variables the bundler fills in;
- the `open-path` event is in the Rust/UI contract on both sides.

The code that receives the event and starts the process is compiled only on macOS, and nothing in CI sends it a Finder event.

**Manual checks for testers.**

macOS (the unsigned app from the release build; Gatekeeper may ask for "Open Anyway" first):
1. Right-click a `.md` file in Finder: **Open With** lists TrailMark. Pick it with TrailMark closed, then with its
   welcome screen showing, then with a project open: the file opens in Simple mode in the first two cases; in the third
   it opens in a new window, unless the file is inside the project that is open, where it opens in that window.
2. Double-click a `.md` file: it still opens in the app that was the default before (TrailMark did not take over).
3. Drag a folder onto the Dock icon, with TrailMark closed, on the welcome screen and with a project open: same three
   outcomes, as a project (the open project's own folder, or one inside it, only brings its window forward).
4. Select three `.md` files and use **Open With**: one window each.
5. Paths with spaces and accents; `open -a TrailMark ~/notes` from a terminal.
6. If the Dock refuses the folder drop, add `CFBundleTypeOSTypes` = `fold` to a merged `src-tauri/Info.plist`.

Linux (the `.deb` or `.rpm` installed; GNOME Files and Dolphin):
1. `grep -E '^(Exec|MimeType)=' /usr/share/applications/trailmark.desktop` shows `Exec=trailmark %f` and
   `MimeType=text/markdown;`; `desktop-file-validate` on it is clean.
2. Right-click a `.md` file, **Open With**: TrailMark is listed and opens the file, also when the name has spaces. The
   list can need `update-desktop-database` or a new session to refresh after installing.
3. Select several `.md` files and open them with TrailMark: one window each.
4. TrailMark is not offered for folders, and `xdg-mime query default inode/directory` is unchanged.
5. Start TrailMark from the application menu: it shows the welcome screen (no stray argument).
